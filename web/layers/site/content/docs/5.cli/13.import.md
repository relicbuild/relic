---
title: Migrating from Artifactory
description: Import a JFrog Artifactory® into Relic with relic import artifactory.
---

`relic import artifactory` copies a JFrog Artifactory® into the Relic server
you are signed in to. It copies:

- groups
- repositories (local, remote and virtual)
- permission targets
- the files of local repositories, with their properties

It only reads the source, through its REST API. It installs and changes nothing
on the source.

Preview the import without changing anything:

```bash
relic import artifactory https://artifactory.example.com --user admin --password-stdin --dry-run
```

Run the import, with the password on standard input:

```bash
relic import artifactory https://artifactory.example.com --user admin --password-stdin
```

Import one repository, with an access token on standard input:

```bash
cat source.token | relic import artifactory https://artifactory.example.com --token-stdin --repository libs-release
```

- Running the command again resumes an interrupted import or picks up changes.
  It leaves alone repositories, groups and permissions that already exist.
  `--update` replaces them. It skips files that Relic already holds with the
  same SHA-256.
- `--repository` limits the repositories and their files. The command still
  copies every group and every permission target.
- The command uploads every file with the checksums the source reports, so
  Relic verifies what it receives. `--workers` sets how many files it copies at
  once (4 by default).
- A federated repository is copied, with its files, as a local repository, and
  the command prints a note for it. Federate it again with a
  [replication](/docs/guides/replication) whose direction is `federated`.
- The command does not copy users. Connect Relic to your LDAP directory, or
  create the users again.
- The command does not copy the caches of remote repositories. Relic fills
  them on demand.
- `-o json` reports what was copied. `-v` lists each item as it is copied.
