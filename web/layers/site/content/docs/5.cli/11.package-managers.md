## Client setup

`relic package setup <client> <repository>` prints the configuration a client
needs to use a repository with your token. It is the same as *Set me up* on the
repository page. With `--write`, the command writes the configuration and runs
the client's own login.

Print the `~/.npmrc` for a repository. The token shows as `<token>`:

```bash
relic package setup npm npm-virtual
```

Write the `~/.npmrc` instead of printing it:

```bash
relic package setup npm npm-virtual --write
```

Write `~/.m2/settings.xml`. Add `--force` to replace an existing one:

```bash
relic package setup maven maven-virtual --write
```

Configure Go, with the modules under `git.example.com` marked as private:

```bash
relic package setup go go-virtual --private 'git.example.com/*' --write
```

Run `docker login` with the token on standard input:

```bash
relic package setup docker docker-virtual --write
```

Configure apt for a Debian distribution. Run this as root, for example in a
Dockerfile:

```bash
relic package setup apt debian-remote --distribution bookworm --write
```

Configure dnf and yum for an RPM repository, as root:

```bash
relic package setup dnf rpm-virtual --write
```

The supported clients are `npm`, `pnpm`, `yarn`, `maven`, `gradle`, `go`, `pip`, `pipenv`,
`poetry`, `twine`, `docker`, `podman`, `nuget`, `conan`, `ruby`,
`terraform`, `helm`, `cargo`, `apk`, `apt`, `dnf`, `nix` and `huggingface`.
`relic package setup --help` lists what each writes.

- User files go under `--home`, which defaults to your home directory.
- System files (`apk`, `apt`, `dnf`) go under `--root`, which defaults to `/`.
- Files that hold the token are written with mode `0600`.
- Some files are shared with other tools (`.npmrc`, `.netrc`, `.terraformrc`,
  …). In these, relic writes a block marked with the repository's name. When
  you run the command again, it replaces only that block.

## Checking a package version

Check whether a package version may be used through a repository. The command
exits with status 1 when Relic refuses the version, for example because it is
malicious, cooling down, quarantined or violates a policy:

```bash
relic package check pkg:npm/lodash@4.17.21 --repository npm-virtual
```

See [AI agents](/docs/guides/ai-agents#routing-an-agents-dependencies) for
every reason a version is refused.

## Publishing

Publish a Go module. The command uploads the module zip, `go.mod` and `.info`:

```bash
relic package publish go go-local v1.4.0 --dir ./lib
```

Publish a Terraform module:

```bash
relic package publish terraform tf-local 1.0.0 --namespace acme --provider aws --dir modules/network
```

Upload a Hugging Face model. The upload becomes a new commit on `main`:

```bash
relic package huggingface upload ./bert-tiny hf-local acme/bert-tiny
```

Download a model at a revision:

```bash
relic package huggingface download hf-remote google-bert/bert-base-uncased ./bert --revision main
```

The publish and upload commands take `--build <name>/<number>`. It records what
the command published in that build run (see [Builds and images](/docs/cli/builds)).

To use a published Terraform module, set
`source = "<host>/tf-local__acme/network/aws"`.
