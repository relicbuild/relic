## Status

Check the server and your sign-in:

```bash
relic auth status
```

Print the same report as JSON:

```bash
relic auth status -o json
```

`relic auth status` reports the server's version, the round-trip time, and the
user your credentials sign in as. For administrators, it also runs the health
checks of the database and object storage. It exits with status 1 when
a check fails, so you can use it as a monitoring probe.

`relic server setup` installs a service on this machine. To check that service,
run `relic server status` ([Machine setup](/docs/cli/setup#status-and-settings)).

## Storage check

Queue a check of stored content against the database (administrators):

```bash
relic storage check
```

Wait for the check and print its report:

```bash
relic storage check --wait
```

The check hands content that no file uses to garbage collection, reports
content that is missing or of the wrong size, and re-hashes a share of the
stored content. With `--wait`, the command exits with status 1 when content is
missing or damaged. Add `-o json` for a report scripts can read. The worker also
runs the check daily ([Operations](/docs/guides/operations#routine-operations)).

## Audit log

List the audit events of the last day (viewers and administrators):

```bash
relic audit list --since 24h
```

`--actor`, `--action`, `--target` and `--outcome` (`success`, `denied` or
`failure`) narrow the list ([Audit log](/docs/guides/security/audit-log)).

## Usage

Print storage, growth, downloads and deploys by repository, project and user
for the last 90 days (viewers and administrators):

```bash
relic usage --days 90
```

The period is 30 days by default, and at most 730
([Usage reports](/docs/guides/operations#usage-reports)).

## Webhooks

Define webhooks as `Webhook` resources. List a webhook's latest deliveries
(viewers and administrators):

```bash
relic webhook deliveries ci-notify
```

Queue a `webhook.ping` event to test the receiver (administrators):

```bash
relic webhook ping ci-notify
```

## Project members

Define projects as `Project` resources ([Projects](/docs/guides/projects)).
Administrators and the project's admins add and remove members one at a time,
leaving the other members as they are.

Add a group to a project as viewers:

```bash
relic project member-add acme qa --group --role viewer
```

Remove a user from a project:

```bash
relic project member-remove acme alice
```

## MCP server and skill registries

List the entries of an `mcp` or `skills` repository. Administrators and
viewers also see the entries that are not approved yet:

```bash
relic registry list mcp-servers
```

Approve an entry's current content, so the registry serves it
(administrators):

```bash
relic registry approve mcp-servers/weather/1.1.0/server.json
```

Withdraw the approval:

```bash
relic registry revoke mcp-servers/weather/1.1.0/server.json
```

See [AI agents](/docs/guides/ai-agents#mcp-server-and-skill-registries).

## Calling the API

`relic api` sends a request with the credentials of the current context. It
prints the response, with JSON indented. A path without a leading `/` is
relative to `/api/v1/`.

Get the server version:

```bash
relic api version
```

List the repositories:

```bash
relic api repositories
```

Send a POST request with a body from a file:

```bash
relic api -X POST 'builds/app/runs/7:promote' -d @promote.json
```

Call a Connect method by its full path:

```bash
relic api /api/relic.v1.SystemService/GetVersion -d '{}'
```

Pass the request body on standard input:

```bash
echo '{"name": "libs-local"}' | relic api /api/relic.v1.RepositoryService/GetRepository -d @-
```

| Flag | Does |
| --- | --- |
| `-d` | sends a body (`@file`, or `@-` for standard input). The method becomes POST unless `-X` sets another |
| `-H 'Name: value'` | adds a header |
| `-i` | prints the status line and headers |

An error response exits with status 1.

## API documentation

`relic api docs` reads the OpenAPI description from the server you are signed
in to, so it matches the server in use.

List every operation with its method, path and summary:

```bash
relic api docs
```

List the operations that match a query:

```bash
relic api docs token
```

Show an operation's parameters, bodies and their schemas:

```bash
relic api docs describe SecurityService_CreateToken
```

Describe an operation by method and path, as JSON:

```bash
relic api docs describe 'GET /api/v1/version' -o json
```

## Access tokens

Create a token that expires in 30 days and export it:

```bash
export RELIC_TOKEN=$(relic auth token create --description ci --expires-days 30)
```

Create a token that acts with the permissions of one group only:

```bash
relic auth token create --group deployers -o json
```

List your tokens. The list does not show the secrets. Administrators and viewers
see every user's tokens, or one user's with `--user`:

```bash
relic auth token list
```

Revoke a token by the full id that `relic auth token list` shows:

```bash
relic auth token revoke 01a14acc-9a25-73a0-b25c-c7f3bb3ab7a5
```

Relic prints a token once and keeps no copy: it stores the token's id and checks
the signature of the token you present. The token works with the Relic API,
`relic` and every package manager client.
