`relic` is the command-line client of the [Relic API](/docs/api/relic-api). The
same binary runs the server. Configuration lives in YAML files that you apply
as with `kubectl apply`.

Commands are grouped by what they act on:

| Group | Does | Page |
| --- | --- | --- |
| `relic server` | runs, installs and inspects the server on this machine | [Machine setup](/docs/cli/setup), [Database](/docs/cli/database) |
| `relic auth` | sign-in, contexts and access tokens | [Sign in and contexts](/docs/cli/sign-in), [Server, API and tokens](/docs/cli/platform) |
| `relic artifact`, `cleanup`, `hold` | files, properties, cleanup policies and legal holds | [Artifacts](/docs/cli/files) |
| `relic apply`, `diff`, `get`, `delete` | declarative configuration | [Resources](/docs/cli/resources), [apply, diff and delete](/docs/cli/apply) |
| `relic build`, `image` | build runs and container image promotion | [Builds and images](/docs/cli/builds) |
| `relic release` | release bundles | [Releases](/docs/cli/releases) |
| `relic evidence` | signed evidence | [Evidence](/docs/cli/evidence) |
| `relic security` | scanning, reports, SBOMs, VEX and waivers | [Scanning and auditing](/docs/cli/security), [Scan reports and VEX](/docs/cli/reports-and-vex) |
| `relic package` | package manager setup and publishing | [Package managers](/docs/cli/package-managers) |
| `relic storage`, `audit`, `usage`, `webhook`, `project`, `registry`, `api` | server checks, audit log, usage, webhooks, projects, registries, API calls | [Server, API and tokens](/docs/cli/platform) |
| `relic replication` | runs a replication now | [Replication](/docs/guides/replication) |
| `relic mcp` | serves Relic's read-only tools to an AI agent | [AI agents](/docs/guides/ai-agents) |
| `relic import` | migrating from Artifactory® | [Migrating from Artifactory](/docs/cli/import) |
| `relic completion` | shell completion scripts | [Artifacts](/docs/cli/files#output-and-completion) |

## Install

Install the latest release for Linux or macOS (amd64 or arm64) into
`~/.local/bin`. The script checks the SHA-256 sum:

```bash
curl -fsSL https://relic.build/install.sh | sh
```

Install a specific release into another directory:

```bash
curl -fsSL https://relic.build/install.sh | sudo env RELIC_VERSION=vX.Y.Z RELIC_INSTALL_DIR=/usr/local/bin sh
```

A Relic server also serves the script at `/install.sh`.

Each [GitHub release](https://github.com/relicbuild/relic/releases) has
archives for Linux and macOS (amd64, arm64) and Windows (amd64, zip), an SBOM
per archive, `relic_<tag>_checksums.txt` and its cosign signature
`relic_<tag>_checksums.txt.sigstore.json`.

To install by hand, set the release and platform (`linux_amd64`, `linux_arm64`,
`darwin_amd64` or `darwin_arm64`):

```bash
v=vX.Y.Z p=linux_amd64
```

Download the archive and the checksum files:

```bash
gh release download "$v" --repo relicbuild/relic -p "relic_${v}_${p}.tar.gz" -p "relic_${v}_checksums.txt*"
```

Optionally, verify the checksum file's signature:

```bash
cosign verify-blob "relic_${v}_checksums.txt" --bundle "relic_${v}_checksums.txt.sigstore.json" --certificate-oidc-issuer https://token.actions.githubusercontent.com --certificate-identity-regexp '^https://github.com/relicbuild/relic/'
```

Check the archive's SHA-256 sum:

```bash
sha256sum -c --ignore-missing "relic_${v}_checksums.txt"
```

Unpack it and install `relic` in `~/.local/bin`:

```bash
tar -xzf "relic_${v}_${p}.tar.gz" && install "relic_${v}_${p}/relic" ~/.local/bin/
```

The archives do not include the scanners; the Relic image does. A server
without syft and grype runs with scanning off.

The image holds the binary at `/relic`. To copy it out, create a container
without starting it:

```bash
docker create --name relic-cli <relic-image>
```

Copy the binary out:

```bash
docker cp relic-cli:/relic ./relic
```

Remove the container:

```bash
docker rm relic-cli
```

Or build it from source in a checkout of the repository:

```bash
go build -o ~/bin/relic ./cmd/relic
```

Next, run `relic server setup` to write the config, add shell completion and
run the server as a service: systemd on Linux, launchd on macOS ([Machine setup](/docs/cli/setup)).
