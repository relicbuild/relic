## Recording a run

You assemble a build run locally, one command at a time, and then publish it.
Runs in progress are stored in `$RELIC_BUILD_DIR`. The default is `builds/`
next to the config file. Because the run is stored on disk, each command can
run in a different step of a CI job.

Record environment variables as `env.<NAME>` properties. Variables with names
that look like secrets are left out:

```bash
relic build collect-env app 42 --include 'CI_*'
```

Record the Git remote (without credentials), branch and revision:

```bash
relic build add-git app 42
```

Upload an artifact and record it in the run with `--build`. The file also gets
the `build.name`, `build.number` and `build.timestamp` properties, so searches
and downloads by build find it:

```bash
relic artifact upload target/app.jar libs-local/org/app/1.0/app.jar --build app/42
```

Record local files as dependencies:

```bash
relic build add-dependencies app 42 vendor/*.jar --type maven --scope compile
```

Record an artifact stored in Relic as a dependency:

```bash
relic build add-dependencies app 42 --from-relic libs-release/org/lib/1.0/lib-1.0.jar
```

Record a container image's manifest and layers, read from Relic:

```bash
relic build add-image app 42 docker-local/team/app:1.4.0
```

Add another published run to this run as a module:

```bash
relic build append release 7 app 42
```

Show what `publish` would send, without sending it:

```bash
relic build publish app 42 --dry-run -o yaml
```

Publish the run:

```bash
relic build publish app 42
```

Forget a run without publishing it:

```bash
relic build clean app 42
```

## Scanning

Scan a run. The command waits for the scan to finish, and exits with status 1
if a violated rule fails builds:

```bash
relic build scan app 42
```

Print the result as JSON, and turn off the failing exit status:

```bash
relic build scan app 42 -o json --fail=false
```

`relic build scan` scans the run's dependencies and adds the existing scans of
the run's artifacts. A dependency whose ID names a package (`name:version`, or
`group:artifact:version` for Maven) is scanned as that package; any other
dependency, such as a file recorded by `relic build add-dependencies`, counts
by its content, like an artifact. The scan then evaluates the policies of the
watches that cover the build.

## Promoting and retention

Promote a run to a repository, set its status and add a property:

```bash
relic build promote app 42 libs-release --status released --props release=1.0
```

Preview a promotion that copies the artifacts and the dependencies:

```bash
relic build promote app 42 libs-staging --copy --dependencies --dry-run
```

Keep the 20 newest runs of `app`, and never discard run `1.0.0`:

```bash
relic build discard app --max-runs 20 --keep 1.0.0
```

Discard runs of `app` older than 90 days, and delete their artifacts too:

```bash
relic build discard app --max-days 90 --delete-artifacts
```

A promotion with an error exits with status 1.

## Container images

Copy an image to another repository:

```bash
relic image promote docker-dev/team/app:1.4.0 docker-prod --copy
```

Promote an image under a new name and tag:

```bash
relic image promote docker-dev/team/app:1.4.0 docker-prod/release/app:stable
```

Promote every tag of an image:

```bash
relic image promote docker-dev/team/app:any docker-archive --all-tags
```

Moving an image needs delete permission on the source. Copying needs read
permission.
