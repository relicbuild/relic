title: Scanning and auditing
description: Scan files, images and SBOMs, audit a project's dependencies, check what Relic would block, and manage policy previews, decisions, quarantine and waivers.
---

`relic security scan` and `relic security audit` catalog packages locally with
[Syft](https://github.com/anchore/syft). They then scan those packages with
Relic Scan on the server, so the results use the server's vulnerability
database and policies.

Install Syft, or point `--syft` at it. With `--sbom`, `relic security scan` skips
cataloging and reads the packages from the SBOM you give. `relic security audit`
has no `--sbom`.

## Files, directories and images

Scan a file:

```bash
relic security scan target/app.jar
```

Scan a local Docker image and an image in a registry:

```bash
relic security scan docker:team/app:1.4.0 registry:relic.example.com/docker/team/app:1.4.0
```

Scan a directory and apply the policies of the watch `prod`:

```bash
relic security scan dist/ --watch prod
```

Scan an SBOM in CycloneDX, SPDX or Syft JSON format:

```bash
relic security scan --sbom bom.cdx.json -o json
```

## A project's dependencies

Audit the lock files and manifests in the current directory:

```bash
relic security audit
```

Audit another directory against the policies of the watch `backend`:

```bash
relic security audit services/api --watch backend
```

`scan` and `audit` exit with status 1 when a violated rule fails builds, so
they can stop a pipeline. `--fail=false` turns that off.

## What Relic would block

Check which dependencies Relic would block when downloaded through `npm-remote`:

```bash
relic security audit --curation --repository npm-remote
```

The command applies the policies of the watches that cover `npm-remote`. It
lists each dependency that Relic would block if you downloaded it through that
repository. It exits with status 1 when it finds any.

## Policy previews

List the stored files that the policies in a file would raise violations on,
without applying them (administrators):

```bash
relic security policy preview -f policies.yaml
```

See [Policies as code](/docs/guides/security/relic-scan#policies-as-code).

## Decisions

List the blocked downloads, builds and promotions (viewers and
administrators). `--kind` takes `download`, `build` or `release`:

```bash
relic security decisions --kind download
```

## Quarantine

List the files that quarantined remote repositories hold (viewers and
administrators):

```bash
relic security quarantine list
```

Serve a held file, whatever its scan says (administrators):

```bash
relic security quarantine release maven-remote/org/acme/lib/1.0/lib-1.0.jar --reason "reviewed"
```

Never serve a held file (administrators):

```bash
relic security quarantine reject maven-remote/org/acme/lib/1.0/lib-1.0.jar --reason "malicious"
```

See [Quarantine](/docs/guides/security/relic-scan#quarantine).

## Waivers

Ask administrators for an ignore rule:

```bash
relic security waiver request --package pkg:npm/lodash@4.17.15 --vulnerability CVE-2020-8203 --reason "the vulnerable function is not reachable"
```

List the pending waivers. You see your own; administrators and viewers see
everyone's:

```bash
relic security waiver list --status pending
```

Approve a waiver for 30 days (administrators). It becomes an ignore rule that
expires then:

```bash
relic security waiver approve 0192f7a0-5d1e-7c3a-9b2f-6e4d8a1c0b7e --days 30
```

Reject a waiver with a note (administrators):

```bash
relic security waiver reject 0192f7a0-5d1e-7c3a-9b2f-6e4d8a1c0b7e --note "upgrade instead"
```

Withdraw one of your pending waivers:

```bash
relic security waiver withdraw 0192f7a0-5d1e-7c3a-9b2f-6e4d8a1c0b7e
```

See [Waivers](/docs/guides/security/relic-scan#waivers).
