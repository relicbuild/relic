---
title: Releases
description: Create, promote, tag, export and import releases.
---

A release version is a signed set of artifacts that cannot change. Its
artifacts come from files, build runs, other releases or a query. Promotion
and export check every stored artifact against the signed manifest, and
refuse a version whose stored files no longer match it.

When you promote a release version to an environment, Relic sends its artifacts
to every repository whose `environments` setting names that environment.

**Releases** in the UI lists the releases and their versions. A version's page
shows its artifacts, promotions, promotion gate decisions and evidence, and
promotes it. **Security → Promotion gates** manages the gates.

Create a release version from a build run and a file:

```bash
relic release create app 1.4.0 --build app/42 --file libs-local/docs/guide.pdf
```

Create a release version from a sources file kept in your repository:

```bash
relic release create app 1.5.0 -f release.yaml
```

Create a draft. You can add more to a draft with `relic release update` before
you finalize it:

```bash
relic release create app 1.6.0 --build app/50 --draft
```

Add another release to the draft:

```bash
relic release update app 1.6.0 --release base/2.1
```

Finalize the draft:

```bash
relic release finalize app 1.6.0
```

List the releases, each with its latest version:

```bash
relic release list
```

List the versions of one release:

```bash
relic release list app -o json
```

Show one version and its artifacts:

```bash
relic release get app 1.4.0
```

Tag a version. Run the command without a tag to clear the tag:

```bash
relic release tag app 1.4.0 stable
```

Promote a version to the `PROD` environment:

```bash
relic release promote app 1.4.0 PROD
```

Promote a version to `QA` into the `qa-generic` repository only:

```bash
relic release promote app 1.4.0 QA --include qa-generic
```

A promotion always copies the artifacts. `--move` is accepted, but the server
performs it as a copy and says so in the promotion's messages.

Delete a version:

```bash
relic release delete app 1.3.0
```

`-f` reads a list of sources in YAML or JSON. Each source has one of `files`,
`builds`, `releases` or `query`. A source is the Relic API's `ReleaseSource`
message:

```yaml
- builds:
    - {name: app, number: "42", dependencies: true}
- files:
    - {path: libs-local/docs/guide.pdf}
```

## Promotion gates

A promotion gate is a condition that a release version must meet before it is
promoted to an environment. If any gate of the target environment refuses,
Relic refuses the promotion. Each gate's decision, allowed or refused, is
recorded as evidence on the version's manifest, with the predicate type
`https://relic.build/promotion-gate/v1`.

The condition is a CEL expression over these variables:

| Variable | Holds |
| --- | --- |
| `release` | `project`, `name`, `version`, `tag`, `createdBy`, and `artifacts`, each with `repository`, `path`, `sha256` and `size` |
| `environment` | the target environment |
| `evidence` | the version's evidence, a list, each with `predicateType`, `predicate`, `verified`, `keyAlias` and `createdBy` |
| `scan` | finding counts: `critical`, `high`, `medium`, `low`, `unknown`, `malicious`, and `unscanned` artifacts |
| `signed` | whether the manifest verifies with Relic's release key and the stored artifacts still match it |

A file with two gates for `PROD`:

```yaml
apiVersion: relic.build/v1
kind: PromotionGate
metadata: {name: prod-clean}
spec:
  environment: PROD
  condition: signed && scan.critical == 0 && scan.malicious == 0 && scan.unscanned == 0
  description: no critical or malicious findings
---
apiVersion: relic.build/v1
kind: PromotionGate
metadata: {name: prod-provenance}
spec:
  environment: PROD
  condition: evidence.exists(e, e.predicateType == "https://slsa.dev/provenance/v1" && e.verified)
  description: verified build provenance
```

Apply the gates:

```bash
relic apply -f gates.yaml
```

List the gates:

```bash
relic get promotiongates
```

## Moving releases between servers

Export a version's artifacts and its signed manifest to a file:

```bash
relic release export app 1.4.0 --file app-1.4.0.zip
```

An administrator imports the file on the other server:

```bash
relic --context airgap release import app-1.4.0.zip
```

Relic signs every version's manifest with its `release-bundles` key pair, and
the file carries that key's public half. Import refuses a file whose manifest
is unsigned, whose signature does not verify, or whose artifacts differ from
the signed list. The importing server logs the SHA-256 of the key's PEM text
(`key_sha256`).

Show the exporting server's public key, to compare with the logged one:

```bash
curl -u admin https://relic.example.com/api/v1/key-pairs/release-bundles/public-key
```
