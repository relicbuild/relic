title: Artifacts
description: relic artifact uploads, downloads, searches, copies, moves and deletes artifacts, and manages their properties; relic cleanup and relic hold run cleanup policies and legal holds.
---

Upload a file to a path in a repository:

```bash
relic artifact upload app-1.0.jar libs-local/org/app/1.0/app-1.0.jar
```

Upload a file into a folder, where it keeps its name (`libs-local/app/app.tar.gz`):

```bash
relic artifact upload dist/app.tar.gz libs-local/app/
```

Download a file to `./app-1.0.jar`:

```bash
relic artifact download libs-local/org/app/1.0/app-1.0.jar
```

Write a file to standard output with `-o -`:

```bash
relic artifact download libs-local/notes.txt -o - | less
```

Search for artifacts. The command prints one `repository/path` per line:

```bash
relic artifact search app-1.0 --repository libs-local
```

Relic checks uploads, downloads and searches against your permissions.

## Copy, move and delete

Copy a file to another repository:

```bash
relic artifact cp libs-local/org/app/1.0/app.jar libs-release/org/app/1.0/app.jar
```

Copy a folder into a folder, as a dry run:

```bash
relic artifact cp libs-local/org/app/1.0 libs-release/org/app/ --dry-run
```

Move several files into a folder:

```bash
relic artifact mv libs-local/a.txt libs-local/b.txt libs-archive/2026/
```

Delete a folder and a file, without failing on items that are already gone:

```bash
relic artifact rm libs-local/org/app/0.9 libs-local/tmp.txt --ignore-not-found
```

- A destination that ends in `/` is a folder. With several sources, the
  destination is always a folder. The sources keep their names in it.
- Folders are copied, moved and deleted with everything below them.
- `--dry-run` checks permissions and conflicts without changing anything.
- Deleted items go to the trash.

## Cleanup policies

A cleanup policy moves old items to the trash. Define policies as
`CleanupPolicy` resources ([Repositories](/docs/guides/repositories#cleanup-policies)).
The worker runs them daily. Viewers and administrators can preview a policy;
administrators can run it.

List what a policy would move to the trash now:

```bash
relic cleanup preview old-snapshots
```

Run it now:

```bash
relic cleanup run old-snapshots
```

## Legal holds

A held item, or a folder with everything under it, cannot be deleted, moved,
overwritten or cleaned up until the hold is released. Administrators place and
release holds ([Repositories](/docs/guides/repositories#legal-holds)).

Place a hold on a folder:

```bash
relic hold add libs-local/org/app/1.4.0 --reason "audit 2026-14"
```

List the holds:

```bash
relic hold list
```

Release the hold:

```bash
relic hold remove libs-local/org/app/1.4.0
```

## Properties

Set properties on a folder and everything below it:

```bash
relic artifact props set libs-local/org/app/1.0 release=1.0 qa=passed,signed --recursive
```

Print the properties of a file, one `key=value` per line:

```bash
relic artifact props get libs-local/org/app/1.0/app.jar
```

Print them as JSON:

```bash
relic artifact props get libs-local/org/app/1.0/app.jar -o json
```

Delete a property from a folder and everything below it:

```bash
relic artifact props delete libs-local/org/app/1.0 qa --recursive
```

`set` replaces the values of the keys it names. It leaves other keys
unchanged.

## Git LFS objects

A Git LFS repository keeps one file per object. Each file is named by the
object's sha256 object id.

Run `relic artifact lfs clean` in a Git working tree. It deletes the objects
that no LFS pointer in the matching references names.

Without a repository argument, the command uses the repository in the `lfs.url`
setting of `.lfsconfig`. Preview the cleanup without deleting anything:

```bash
relic artifact lfs clean --dry-run -v
```

Clean a named repository against the local branches and tags, with JSON output:

```bash
relic artifact lfs clean lfs-local --refs 'refs/heads/**,refs/tags/**' -o json
```

`--refs` defaults to `refs/remotes/**`, the remote-tracking branches of every
remote the working tree knows. The patterns are `git for-each-ref` patterns, in
which `*` stops at a `/` and `**` does not. The command leaves alone any file
whose name does not look like an LFS object id.

## Output and completion

Most commands that print a list or a report take `-o text|json|yaml`;
`relic <command> --help` shows whether a command has it. `relic get` takes
`-o text|name|yaml|json`; `name` prints one name per line. In `relic artifact download`, `-o` names the file to
write instead, or a directory (one that exists, or a path ending in `/`) to write
it into under its own name.

In text mode a list is printed as a table, with sizes in binary units
(`1.5 KiB`). Scripts should read `-o json`: the table's layout is for people
and may change.

On a terminal, a command that takes more than a moment shows a spinner on
standard error until it is done; lines the command prints appear above it.
Nothing is drawn when standard error is not a terminal, so pipes and CI logs
stay clean. Commands that ask a question (`relic auth login`,
`relic server setup`, `stop` and `uninstall`) show none.

`relic completion bash|zsh|fish|powershell` prints a shell completion script.
The script completes repository names and paths from the server.
