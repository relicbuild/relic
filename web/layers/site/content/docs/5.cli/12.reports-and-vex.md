---
title: Scan reports and VEX
description: Show what Relic Scan found in a stored file, list operational risks, and exchange ignore rules as OpenVEX or CycloneDX VEX.
---

## A stored file's scan

Show what Relic Scan found in a stored file: vulnerabilities, malicious
packages, secrets, misconfigurations and operational risks:

```bash
relic security report libs-local/org/app/1.0/app.jar
```

Exit with status 1 when a finding, issue or operational risk is high severity or worse:

```bash
relic security report charts/demo-0.1.0.tgz --fail-on high
```

For an image tag folder, the report shows the scan of the tag's manifest:

```bash
relic security report docker-local/team/app/1.4.0 -o json
```

## Operational risks

List the components past or near end of life, deprecated or unmaintained, in
every stored file:

```bash
relic security risks
```

List one kind in one repository, as JSON:

```bash
relic security risks --kind end_of_life --repository libs-local -o json
```

## SBOMs

Write an item's SBOM as CycloneDX (the default), SPDX or Syft JSON:

```bash
relic security sbom export libs-local/app/app-1.4.0.jar --format cyclonedx > app.cdx.json
```

Replace an item's SBOM with one your build made, and have it matched again:

```bash
relic security sbom import libs-local/app/app-1.4.0.jar build/bom.json
```

For a container image, give the image's folder, for example
`docker-local/web/1.2`.

## VEX

Export the ignore rules as OpenVEX `not_affected` statements:

```bash
relic security vex export > relic.vex.json
```

Export them as CycloneDX, with the Go vulnerabilities no code calls:

```bash
relic security vex export --format cyclonedx --unreachable --file relic.cdx.json
```

Import an OpenVEX or CycloneDX document's `not_affected` and `fixed` (`resolved`)
statements as ignore rules:

```bash
relic security vex import vendor.vex.json
```

Both commands need an administrator, as ignore rules do.

## The vulnerability database

On an installation without Internet access, import the vulnerability database
from a file:

```bash
relic security database import grype-db.tar.zst
```

Show the state of the vulnerability database:

```bash
relic security database status
```

## End-of-life data

On an installation without Internet access, import endoflife.date's product
data from a file:

```bash
relic security end-of-life import eol.json
```

Show where the end-of-life data came from and when:

```bash
relic security end-of-life status
```
