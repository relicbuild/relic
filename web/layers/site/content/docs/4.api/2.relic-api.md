title: Relic API
description: Relic's own API, defined in protobuf and served as REST, Connect and gRPC-Web.
---

The web UI, the `relic` CLI and scripts use the Relic API. Its schema is the
protobuf files in `api/proto/relic/v1` in the Relic repository. Every method is
served in three ways under `/api/`. The same handlers serve all three, with the
same access checks:

| Protocol | Request |
| --- | --- |
| REST | resource URLs under `/api/v1/`, such as `GET /api/v1/repositories/libs-local` or `PUT /api/v1/users/alice`. The [API reference](/api-reference) lists every method's route. |
| Connect | `POST /api/relic.v1.<Service>/<Method>` with a JSON (or binary protobuf) body. The web UI and the `relic` CLI use it. |
| gRPC-Web | the same paths as Connect, for generated clients in any language |

Native gRPC needs HTTP/2. The server speaks HTTP/1.1 only, without h2c, so
gRPC clients cannot call it. Use a Connect or gRPC-Web client instead.

JSON encoding follows these rules:

- Field names are the proto names in lowerCamelCase (`deploy_to` is `deployTo`).
- Enums are their names (`REPOSITORY_CLASS_LOCAL`), in REST query strings too
  (`?class=REPOSITORY_CLASS_LOCAL`).
- 64-bit integers are JSON strings.

## Authentication and access

Send Basic credentials (`-u user:password-or-token`) or an
`Authorization: Bearer <token>` header. The web UI's session cookie also works
under `/api/`. Writes made with the cookie need the `X-Relic-UI: 1` header.

Every method declares its access level in the proto (`option (relic.v1.access)`):

| Access | Who may call it |
| --- | --- |
| `PUBLIC` | anyone, signed in or not |
| `AUTHENTICATED` | any signed-in user. Items are still checked against permissions. |
| `VIEWER` | viewers and administrators: administration methods that only read |
| `ADMIN` | administrators: administration methods that change something |

Errors use Connect's codes. Over REST, each code maps to an HTTP status:

| Code | HTTP status (REST) |
| --- | --- |
| `unauthenticated` (sign in) | 401 |
| `permission_denied` | 403 |
| `not_found` (also returned for what the caller may not read) | 404 |
| `invalid_argument` | 400 |
| `already_exists` | 409 |
| `failed_precondition` | 400 |
| `unavailable` | 503 |

The error body is `{"code": "...", "message": "..."}` over Connect and
`{"code": <number>, "message": "..."}` over REST.

\* administrators, and the project's admins: for a repository, the admins of
the project it belongs to.

- Builds, releases and evidence check the caller's build, release and item
  permissions on each call. A release's source is files, builds, other
  releases or an `ItemQuery` (criteria on item fields, properties and builds).
- `ListTokens` and `RevokeToken` cover the caller's own tokens. For an
  administrator, they cover everyone's tokens. A viewer lists everyone's tokens
  and revokes only their own.
- `ListProjects` and `GetProject` show the projects the caller is a member of;
  administrators and viewers see all. `ListWaivers` lists the caller's own
  waivers; administrators and viewers see everyone's. `ListRegistryEntries`
  shows entries not yet approved to administrators and viewers only.
- `Put…` methods create or replace (REST `PUT`, usually
  `/api/v1/<collection>/<name>`).
- Secrets (passwords, a remote repository's password, an LDAP manager password,
  a webhook's secret, an identity provider's client secret) are write-only, and
  the API never returns them. An update without a secret keeps the stored value.

## File contents

Messages never carry file bytes. File contents use plain HTTP, with the same
credentials and permission checks:

| Request | Does |
| --- | --- |
| `GET`/`HEAD /api/v1/files/<repo>/<path>` | download (ranges supported) |
| `PUT /api/v1/files/<repo>/<path>` | upload; each query parameter sets a property (`?build.name=app&build.number=42`); answers with the item as JSON |
| `GET /api/v1/archive/<repo>/<path>?entry=<entry>` | one entry of a zip or tar file |
| `GET /api/v1/sbom/<repo>/<path>?format=cyclonedx\|spdx\|syft` | the item's SBOM as CycloneDX 1.6, SPDX 2.3 or Syft JSON (read permission) |
| `PUT /api/v1/sbom/<repo>/<path>` | replace the item's SBOM with a CycloneDX, SPDX or Syft JSON document (deploy permission on every file with the item's content) |
| `POST /api/v1/releases/import` | import a release archive (administrators) |
| `PUT /api/v1/vulnerability-database` | import a vulnerability database archive (administrators) |
| `PUT /api/v1/end-of-life-data` | import endoflife.date's product data (administrators) |

## Examples

Get Relic's version (public):

```bash
curl -s https://relic.example.com/api/v1/version
```

List the repositories you may read:

```bash
curl -s -u <user>:<token> https://relic.example.com/api/v1/repositories
```

Get one of them:

```bash
curl -s -u <user>:<token> https://relic.example.com/api/v1/repositories/libs-local
```

Create a local Maven repository (administrators):

```bash
curl -s -u <user>:<token> -H 'Content-Type: application/json' \
  https://relic.example.com/api/v1/repositories \
  -d '{"name":"libs-local","class":"REPOSITORY_CLASS_LOCAL","format":"FORMAT_MAVEN"}'
```

List a folder's children:

```bash
curl -s -u <user>:<token> https://relic.example.com/api/v1/repositories/libs-local/children/org/app
```

Get an item's details:

```bash
curl -s -u <user>:<token> https://relic.example.com/api/v1/repositories/libs-local/details/org/app/1.0/app-1.0.jar
```

Get the `libs-local` repository over Connect with `GetRepository`:

```bash
curl -s -u <user>:<token> -H 'Content-Type: application/json' -d '{"name":"libs-local"}' \
  https://relic.example.com/api/relic.v1.RepositoryService/GetRepository
```

Upload a file:

```bash
curl -s -u <user>:<token> -T app-1.0.jar https://relic.example.com/api/v1/files/libs-local/org/app/1.0/app-1.0.jar
```

Download it:

```bash
curl -s -u <user>:<token> -O https://relic.example.com/api/v1/files/libs-local/org/app/1.0/app-1.0.jar
```
