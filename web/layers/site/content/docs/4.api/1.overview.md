The web UI and the [relic CLI](/docs/cli/overview) both use the Relic API.

| Property | Value |
| --- | --- |
| Schema | protobuf, `api/proto/relic/v1` |
| Protocol | ConnectRPC under `/api/`: the Connect protocol (JSON or binary protobuf) and gRPC-Web, over HTTP/1.1. Native gRPC needs HTTP/2, which the server does not serve. |
| REST | every method also answers a path under `/api/v1/` |
| File contents | plain HTTP under `/api/v1/files/` |
| Reference | the [API reference](/api-reference) lists every service method, and the file, archive, release import and vulnerability database routes under `/api/v1`. The SBOM routes and the end-of-life data import are listed in [File contents](/docs/api/relic-api#file-contents). |
| OpenAPI | generated from the protobuf definitions and served at `/api/v1/openapi.json` |
| Command-line search | `relic api docs` |

For details, see [Relic API](/docs/api/relic-api). For client libraries, see
[SDK](/docs/sdk/overview).

## Authentication

| Method | Usage |
| --- | --- |
| Basic | `curl -u <user>:<password-or-token> https://relic.example.com/api/v1/repositories` |
| Bearer | `curl -H "Authorization: Bearer <token>" ...` |
| Session cookie | the UI's cookie, honoured under `/api/`. Writes need the `X-Relic-UI` header. |

## Examples

List the repositories over REST:

```bash
curl -u <user>:<token> https://relic.example.com/api/v1/repositories
```

Get the item details that the UI shows:

```bash
curl -u <user>:<token> https://relic.example.com/api/v1/repositories/libs-local/details/org/app/1.0/app-1.0.jar
```

List the repositories with the relic CLI, once you are signed in:

```bash
relic api repositories
```
