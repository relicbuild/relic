---
title: Projects
description: Group repositories into projects, with members in roles and a storage quota.
---

A project has a key, members in roles and an optional storage quota. A
repository belongs to the project its `project` setting names. Members get
their role's actions on the project's repositories:

| Role | In the project's repositories |
| --- | --- |
| `admin` | read, deploy, annotate and delete; manage the project's members and repositories |
| `developer` | read, deploy, annotate and delete |
| `viewer` | read |

A member is a user, or a group (`group: true`). Project roles add to
permissions; they never take a permission away. The storage quota bounds the
files of all the project's repositories together: a deploy that would exceed
it is refused. Deploys to different repositories at the same moment may each
pass the check.

**Projects** in the UI lists the projects you are a member of (administrators
and viewers see all), with their members, repositories and storage. Projects
are `relic.build/v1` resources:

```yaml
apiVersion: relic.build/v1
kind: Project
metadata: {name: acme}
spec:
  name: Acme
  storageQuotaBytes: 107374182400
  members:
    - {name: alice, role: admin}
    - {name: developers, group: true, role: developer}
```

An administrator applies the file:

```bash
relic apply -f projects.yaml
```

A project admin adds a member:

```bash
relic project member-add acme bob --role viewer
```

A project admin removes a member:

```bash
relic project member-remove acme bob
```

These commands change one member and leave the others as they are, so two
admins changing members at the same time both keep their change.

A project admin creates a repository in the project:

```yaml
apiVersion: relic.build/v1
kind: Repository
metadata: {name: acme-libs}
spec: {class: local, format: maven, project: acme}
```
