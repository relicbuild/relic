---
title: Access tokens
description: Scoped access tokens for the relic CLI, CI and the Relic API.
---

A token's scope is one of these:

- your own permissions
- a group's permissions, without the permissions and project roles given to you by name
- admin

A token created with a scoped token cannot have a wider scope than that token,
and a scoped token cannot approve a CLI sign-in. Signing in to the UI with a
token as the password gives a session with that token's scope. When you revoke a
token, the revocation takes effect at once on every replica.

## Lifetimes

| Token | Lifetime |
| --- | --- |
| A token you create (`relic auth token create`, **Access tokens** in the UI) | The lifetime you choose. A token of a user who is not an administrator lasts at most 365 days, also when it is asked never to expire. Administrators can choose up to 3650 days, or no expiry. |
| The token `relic auth login` saves | 90 days by default (`--expires-days`), within the same limits. `relic auth logout`, and signing in again to the same context, revoke it. |
| The token `relic package setup` gives a package manager | 90 days by default (`--expires-days`), within the same limits. |
| A UI session | 12 hours. |
| A CLI sign-in approved in the browser | One hour, and refreshable. `relic auth login` trades it at once for the token it saves. The JFrog® CLI (`jf login`) keeps it and refreshes it. |
| A workload identity's token | An hour at most. See [Workload identities](/docs/guides/security/workload-identities). |

A token or a session stays valid until it expires or is revoked. Changing the
user's password does not end it, and neither does removing the user from the
LDAP directory or the identity provider. Disabling the user in Relic suspends
their tokens and sessions until the user is enabled again, and deleting the user
revokes them. To cut a user off at once, disable the user, or revoke their
tokens.
