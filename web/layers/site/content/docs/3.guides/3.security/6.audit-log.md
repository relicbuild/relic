---
title: Audit log
description: Who changed which setting, who signed in, which tokens were created and which downloads were blocked.
---

Relic records an audit event for:

- every change to administration settings: users, groups, permissions,
  repositories, project members, LDAP, replication, cleanup policies, holds, security
  policies, watches, ignore rules, trusted keys and the trash can, made
  through the Relic API or the Artifactory® API;
- sign-ins to the web UI and approvals of command-line sign-ins, successful
  or not;
- access tokens created and revoked;
- downloads that a security policy blocked;
- SBOM imports (`sbom.import`), which replace the findings of every file with
  the same content.

Refused attempts are recorded too: the outcome of an event is **Succeeded**,
**Denied** (the caller was not signed in or not allowed) or **Failed**. Reads
and artifact deploys are not audited. The request log and the download
statistics hold those.

Each event names its time, the user who acted (the actor), the action (the
API method or route), its target, its outcome and the client's address.

## Reading the log

Administrators and viewers read the log in **Administration → Audit log**,
filtered by user, action, target, outcome and period.

List the last day's events with the CLI:

```bash
relic audit list --since 24h
```

List one user's refused attempts:

```bash
relic audit list --actor bob --outcome denied
```

Add `-o json` or `-o yaml` for output scripts can read, and `--page` and
`--page-size` to page through a long log. The Relic API method is
`AuditService.ListAuditEvents` (`GET /api/v1/audit-events`).

## Retention and export

The worker deletes events older than `RELIC_AUDIT_RETENTION` (365 days) once a
day.

Relic also writes every event to its log as a `relic.audit` line with the
actor, action, target, outcome and client. When log export is on
([Monitoring](/docs/guides/monitoring)), the OpenTelemetry collector forwards
these lines to your SIEM with the rest of Relic's logs.
