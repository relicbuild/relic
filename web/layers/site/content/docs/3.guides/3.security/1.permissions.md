---
title: Permissions
description: Grant users and groups actions on repositories, builds and releases.
---

A permission grants actions to users and groups through rules, at most one per kind:

| Rule | Covers | Selects |
| --- | --- | --- |
| Repository | items | repositories by name, or all, all local or all remote; Ant-style include and exclude patterns narrow the paths |
| Build | published builds | `<build name>/**` patterns |
| Release | release versions | `<release>/<version>` patterns |

The actions are read, annotate, deploy (write), delete, promote (releases) and manage (all).
Creating a release also needs read on its content; promoting one needs write on the target
repositories.

Administrators can do everything; other users, what a rule or their
[project](/docs/guides/projects) role grants. An item's **Permissions** tab shows who may do
what on it.

All, all local and all remote leave out the repositories Relic writes itself (build
information, releases and evidence); a repository rule reaches them only by naming them.
Build and release rules govern access to builds and releases.

A **viewer** sees the administration and security pages without changing
them, and gets no repository access. Turn on **Viewer** for a user, or **Viewer privileges**
for a group.

Manage permissions in **Administration → Permissions**, or declare `Permission` resources and
run `relic apply`.
