---
title: Workload identities
description: CI jobs sign in with the OIDC token their platform issues, for a Relic token that lives an hour at most, without stored secrets.
---

A CI job does not need a stored Relic token. GitHub Actions, GitLab CI,
Buildkite and cloud workload identities give each job a signed OIDC token
that says which repository, branch or pipeline it runs for. A workload
identity tells Relic which issuer to trust and which jobs act as which Relic
user. The job exchanges its token for a Relic token that lives an hour at
most.

## Create a workload identity

Declare the issuer, the audience the tokens must name, and rules. The first rule
whose claims all match decides who the token acts as. Patterns are Ant-style:
`*` matches within a path segment and `**` across segments.

```yaml
apiVersion: relic.build/v1
kind: WorkloadIdentity
metadata:
  name: github
spec:
  enabled: true
  issuer: https://token.actions.githubusercontent.com
  audience: relic
  rules:
    - claims:
        repository: my-org/*
        ref: refs/heads/main
      user: ci-release
    - claims:
        repository: my-org/*
      user: ci-build
      groups: [readers]
```

Apply the file:

```bash
relic apply -f workload-identity.yaml
```

Or create it in **Administration → Workload identities**. A rule's `groups`
narrow the token to those of the user's groups. Tokens, API keys and UI
sessions created with the job's token expire when it does, have no refresh
token, and it cannot approve a CLI sign-in. Relic reads the issuer's
signing keys from its discovery document. For an issuer Relic cannot reach,
paste its keys as `jwks`. `tokenLifetimeMinutes` shortens the tokens below an
hour.

## Exchange the token in CI

In GitHub Actions, give the job `id-token: write`, then sign in with the
relic CLI:

```yaml
permissions:
  id-token: write
steps:
  - run: |
      ID_TOKEN=$(curl -sH "Authorization: bearer $ACTIONS_ID_TOKEN_REQUEST_TOKEN" \
        "$ACTIONS_ID_TOKEN_REQUEST_URL&audience=relic" | jq -r .value)
      relic auth login https://relic.example.com --identity github --oidc-token "$ID_TOKEN"
      relic artifact upload dist/app.tar.gz libs-local/app/
```

In GitLab CI, request an ID token for the audience:

```yaml
release:
  id_tokens:
    RELIC_ID_TOKEN:
      aud: relic
  script:
    - relic auth login https://relic.example.com --identity gitlab --oidc-token "$RELIC_ID_TOKEN"
```

The JFrog® CLI exchanges the token with `jf exchange-oidc-token`; the
workload identity's name is its provider name:

```bash
jf eot github "$ID_TOKEN" --url https://relic.example.com
```

The Relic API method is `SessionService.ExchangeWorkloadToken`
(`POST /api/v1/workload-tokens`). Every exchange, granted or refused, is in
the [audit log](/docs/guides/security/audit-log) as `workload.exchange`.
