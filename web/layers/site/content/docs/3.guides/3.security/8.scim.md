---
title: SCIM provisioning
description: Let your identity provider create, update, disable and delete Relic users and groups through SCIM 2.0.
---

Relic serves SCIM 2.0 at `https://relic.example.com/scim/v2`, so an identity
provider (Okta, Entra ID, OneLogin, JumpCloud) keeps Relic's single sign-on
users and their groups in step with its own directory. Users provisioned this
way sign in through [single sign-on](/docs/guides/security/single-sign-on).

## Connect the identity provider

1. Create an access token for an administrator, for example a service account
   that only provisions. In **Administration → Access tokens**, or with the CLI:

   ```bash
   relic auth token create --scope admin --description scim --expires-days 365
   ```

2. At the identity provider, set the SCIM base URL to
   `https://relic.example.com/scim/v2` and the authentication to a bearer token
   (Entra ID calls it the secret token), with the token from step 1.
3. Map the provider's user name (for example `userPrincipalName` or the login)
   to `userName`. It becomes the Relic username.

## What Relic accepts

| Resource | Operations |
| --- | --- |
| `Users` | create, read, list, filter `userName eq "…"`, replace, patch (`active`, `emails`), delete |
| `Groups` | create, read, list, filter `displayName eq "…"`, replace, patch members (add, remove, replace), delete |
| `ServiceProviderConfig`, `ResourceTypes`, `Schemas` | read |

- SCIM sees only single sign-on users. A local or LDAP account with the same
  user name makes a create fail with `409 uniqueness`, so the identity provider
  cannot take an account over.
- `active: false` disables the user: they cannot sign in, and their access
  tokens stop working until the user is active again. An administrator can
  also disable or enable any user in **Administration → Users**.
- User names and group names cannot change (`400 mutability`). Deprovision
  and provision again to rename. Filters and updates match names in any case.
- Relic keeps one email address per user: the primary one, else the work one.
  Changes to other addresses (`emails[type eq "home"]`) are ignored.
- A group's SCIM ID is its name. Groups SCIM creates are ordinary Relic
  groups: give them permissions, or make their members administrators or
  viewers, as for any group. The members SCIM manages are kept apart from the
  ones an administrator adds, so each side changes only its own.
- SCIM lists every Relic group and can manage the members of any group that
  grants no administrator or viewer rights. A group that does is changed only
  in Relic (`400 mutability`). SCIM deletes a group only while all its
  members are ones SCIM manages. Keep the SCIM token as safe as an
  administrator's password all the same: it creates, disables and deletes
  users.
- Names, titles, external IDs and extension attributes are accepted and
  ignored. Bulk operations, sorting and ETags are not supported.

Every SCIM change is in the [audit log](/docs/guides/security/audit-log), under
the token's user.

When the identity provider also sends a groups claim at sign-in, it replaces
the same memberships SCIM manages. Use one or the other for groups.
