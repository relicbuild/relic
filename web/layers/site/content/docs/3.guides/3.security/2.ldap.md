---
title: LDAP
description: Sign users in against LDAP directories and map directory groups to Relic groups.
---

Manage directories in **Administration → LDAP**, or declare `LdapServer` and
`LdapGroupMapping` resources and run `relic apply`.

## Sign-in

- When a user Relic does not know signs in, Relic checks each enabled directory in key order.
- If the check succeeds and **Create users on first sign-in** is on, Relic creates the
  account in the `ldap` realm. If the setting is off, only accounts that an administrator
  created in the LDAP realm can sign in.
- Local users are never checked against a directory, so a directory entry with
  the same name (for example `admin`) cannot take over a local account.
- Directory users can authenticate in every way local users can: `relic auth login`, package
  managers with Basic credentials, access tokens, `docker login` and the UI.

## Finding users

Relic finds a user's entry in one of two ways. Set one of them:

- A user DN pattern, relative to the base DN in the URL, such as
  `uid={0},ou=people`.
- A search filter, such as `uid={0}`, under a search base. The search needs a manager DN and
  password.

Relic also reads groups with the manager account, because many directories do not let ordinary
users read groups.

## TLS

Use an `ldaps://` URL, or turn on **Use StartTLS** for an `ldap://` URL. Relic verifies the
directory server's certificate against the system roots and the CA certificates in
`RELIC_LDAP_CA_CERTIFICATE_FILE`. In the Helm chart, this setting is `ldap.caCertificate`.

## Groups

A group setting tells Relic where the directory keeps groups:

| Strategy | Meaning |
| --- | --- |
| Static | groups list their members, as with `groupOfUniqueNames` and `uniqueMember` |
| Dynamic | users list their groups, as with `memberOf` |
| Hierarchy | the units in the user's DN, named by the mapping's unit attribute (`ou` unless set) |

On every sign-in, Relic adds the user to the Relic groups whose names match their
directory groups. The match ignores case. Relic also removes the user from groups the
directory no longer lists. Memberships that an administrator set by hand stay. Create the groups under
**Administration → Groups** and give them
[permissions](/docs/guides/security/permissions).

## When a directory is down

Relic refuses sign-in for that directory's users. Local users keep working. Relic reuses a
successful check for up to five minutes, as it does for local passwords. A password changed in
the directory can therefore keep working for up to five minutes.

## The manager password

With `RELIC_ENCRYPTION_KEY` set, Relic seals the manager password with it. Without the
key, Relic stores the password unencrypted. The API and the UI never return it. To keep
the stored password when you edit a setting, leave the field empty. This works only while
the manager DN stays the same. When you change the manager DN, enter the password again,
because an empty field then removes the stored one.

## Test before you save

Enter a directory user's credentials in the setting's form and choose **Test**.
The result shows the DN, email and groups that Relic found.
