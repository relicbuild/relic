---
title: Single sign-on
description: Users sign in with their identity provider's account, through OpenID Connect or SAML, with their groups.
---

Users can sign in with the account they have at an identity provider (Entra ID,
Okta, Keycloak, Google, Auth0 or any OpenID Connect or SAML 2.0 provider).
Each enabled provider adds a button to the sign-in page.

A provider signs in only its own single sign-on accounts: the ones it created,
and ones [SCIM](/docs/guides/security/scim) created, which become the account of
the first provider that signs them in. It never signs in another provider's
account, or a local or LDAP account, with the same name. Deleting a provider
lets the next provider that signs in one of its accounts take it over.
`relic auth login <url>` without
`--user` has you approve the sign-in in the browser, so the CLI signs in through
the same providers. `jf login` does the same for the JFrog® CLI.

## OpenID Connect

1. At the provider, register a web application for Relic. Its redirect URI is
   `https://relic.example.com/api/v1/sso/<name>/callback`, where `<name>` is the
   name you give the provider in Relic.
2. In Relic, open **Administration → Single sign-on**, add an identity
   provider, choose **OpenID Connect**, and enter the provider's issuer URL and
   the client ID and secret it gave you.

Relic uses the authorization-code flow with PKCE and checks the ID token's
signature, audience and nonce. It reads the provider's discovery document from
`<issuer>/.well-known/openid-configuration`, so the Relic server must reach the
issuer. The issuer and a SAML metadata URL must be `https`; plain `http` works
only for a provider on the Relic server's own machine.

Or declare the provider and apply it:

```yaml
apiVersion: relic.build/v1
kind: IdentityProvider
metadata:
  name: corp
spec:
  displayName: Corp account
  enabled: true
  autoCreateUsers: true
  groupsClaim: groups
  oidc:
    issuer: https://login.example.com
    clientId: relic
    clientSecret: <client secret>
```

Apply the file:

```bash
relic apply -f identity-provider.yaml
```

The client secret is write-only: Relic never returns it, and an update
without one keeps the stored secret. With `RELIC_ENCRYPTION_KEY` set, Relic stores
it encrypted.

## SAML 2.0

1. In Relic, add an identity provider, choose **SAML 2.0**, and enter the
   identity provider's metadata URL, or paste its metadata XML when the Relic
   server cannot reach it.
2. Give the identity provider Relic's metadata URL,
   `https://relic.example.com/api/v1/sso/<name>/metadata`. It names Relic's
   entity ID (the same URL), the assertion consumer service
   (`.../api/v1/sso/<name>/acs`, HTTP-POST) and Relic's certificate, which Relic
   generates for each provider.

Relic sends signed authentication requests and accepts only signed responses
or assertions for itself, posted to its assertion consumer service in answer
to a request it made: a response cannot be replayed, and sign-ins the identity
provider starts on its own are refused. Encrypted assertions are decrypted with
Relic's key.

The username is the assertion's NameID, or the attribute **Username
attribute** names. Relic reads the email address from the `email` or `mail`
attribute.

```yaml
apiVersion: relic.build/v1
kind: IdentityProvider
metadata:
  name: adfs
spec:
  displayName: Corp account
  enabled: true
  groupsClaim: http://schemas.microsoft.com/ws/2008/06/identity/claims/groups
  saml:
    metadataUrl: https://adfs.example.com/FederationMetadata/2007-06/FederationMetadata.xml
```

SAML sign-in needs Relic served over HTTPS: the identity provider posts its
answer from another site, and browsers send Relic's sign-in cookie with such a
post only over HTTPS.

## Accounts and groups

| Setting | Effect |
| --- | --- |
| Create users on their first sign-in (`autoCreateUsers`) | A user Relic does not know gets an account, in the groups new users join. Otherwise, only accounts that exist can sign in. |
| Username claim (`usernameClaim`) | The claim or attribute holding the Relic username: `preferred_username` (OIDC) or the NameID (SAML) when empty. |
| Groups claim (`groupsClaim`) | The claim or attribute listing the user's groups. On every sign-in, the user becomes a member of exactly the Relic groups the claim names, compared without case. Groups that do not exist in Relic are ignored. Memberships an administrator set are kept. |

Make a group's members administrators or viewers in **Administration →
Groups**, and grant it permissions as usual. Every sign-in through a provider,
and every refused one, is in the [audit log](/docs/guides/security/audit-log)
as `sso.sign-in`.
