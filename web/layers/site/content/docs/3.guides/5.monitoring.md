Relic exports Prometheus metrics, OpenTelemetry traces and structured logs.
`deploy/observability/` holds seven Grafana dashboards and a set of alert rules.
The Helm chart and the Docker Compose stack can install them. See
[Kubernetes: Monitoring](/docs/installation/kubernetes/monitoring) and
[Compose: Observability profile](/docs/installation/docker/compose-settings#observability-profile).
The settings are listed in the [configuration reference](/docs/installation/configuration#telemetry).

## Metrics

The server and the worker each serve `/metrics` on a separate metrics port
(`RELIC_METRICS_LISTEN_ADDRESS`, default `:8091`). The API port never serves
metrics, so an ingress in front of Relic cannot expose them. The metrics port has
no authentication, so keep it inside your network. Set
`RELIC_PROFILING_ENABLED=true` to add Go's profiler at `/debug/pprof/` on the
same port.

Every series name starts with `relic_`. The [metrics reference](/docs/guides/metrics-reference)
lists each series with its labels. The series cover these areas:

| Area | Series |
| --- | --- |
| HTTP | per API family (`relic`, `packages` for the package and file APIs, `container-registry`, `scanning`, `access`, `releases`, `evidence`, `ui`, `health`), route pattern, method and status class |
| Relic API | per service, method and Connect code |
| Auth | sign-in attempts, issued tokens, LDAP operations |
| Artifacts | uploads and downloads by format, repository class and source (`local`, `cache`, `upstream`); the upstreams of remote repositories and their cache results |
| Storage and database | object storage operations; the database pool and query latency by sqlc query name |
| Background work | jobs by kind, their queues, Relic Scan, garbage collection, the trash can, push replication, builds and releases |
| Inventory | counted by the worker every five minutes: repositories, stored bytes and blobs, unreferenced bytes, users, builds, findings by severity, CVE feed ages |

Labels never hold a user, path, digest, token or address. The one exception is
the repository name, which is off by default. `RELIC_METRICS_REPOSITORY_LABEL=true`
adds it to the artifact, upstream, cache and replication series. The number of
those series then grows with the number of repositories.

## Traces

Set `OTEL_EXPORTER_OTLP_ENDPOINT` (OTLP over HTTP) to trace every request. A
request's trace contains:

- a server span named after the route (`PUT /maven/`)
- the Relic API method
- database queries and object storage operations
- calls to upstream registries, which receive the `traceparent` header
- LDAP and the deploy itself

A job that a request queues, such as a replication or a graph scan, gets a span
linked to that request. Relic honours a caller's `traceparent`, so the spans of a
traced CI job join Relic's spans. Health probes are not traced.

`OTEL_TRACES_SAMPLER` sets how many traces Relic keeps. The Helm chart keeps 10%
of new traces and follows the decision of a traced caller. Compose keeps every
trace.

## Logs

Relic writes JSON lines to stderr at the level set by `RELIC_LOG_LEVEL`. For a
terminal, set `RELIC_LOG_FORMAT=text`. Each request line has a `request_id`,
which Relic also returns in the `X-Request-Id` response header. Traced requests
add `trace_id` and `span_id`. Ship stderr with your log collector, such as Alloy,
Promtail or Fluent Bit. With `OTEL_LOGS_EXPORTER=otlp`, Relic also sends each
record over OTLP.

## Dashboards

| Dashboard | Answers |
| --- | --- |
| Relic / Overview | Is Relic healthy? Traffic, errors and latency per API family, saturation, logs by request or trace ID. |
| Relic / Packages and repositories | Uploads and downloads by format, bytes, remote cache hit ratio, upstream latency and errors, builds and releases. |
| Relic / Storage and garbage collection | Stored and unreferenced content, object storage operations, garbage collection, the trash can. |
| Relic / Relic Scan | Backlog, scans and their stages, findings, blocked downloads, scanner database and CVE feed ages. |
| Relic / Jobs and worker | Jobs by kind, their queues, push replication. |
| Relic / Database | The connection pool and the slowest queries. CloudNativePG's dashboard covers PostgreSQL itself. |
| Relic / Go runtime | CPU, memory, goroutines, garbage collection. |

Each dashboard has the `datasource`, `namespace` and `instance` variables. On a
latency panel, an exemplar opens its trace in Tempo. `go run ./tools/dashgen`
generates the dashboard files.

## Alerts

| Alert | Fires when | Severity |
| --- | --- | --- |
| RelicDown | no server has been scraped for 5 minutes | critical |
| RelicHighErrorRate | over 5% of an API family's requests answer 5xx for 10 minutes | critical |
| RelicDownloadLatencySLO | downloads burn the error budget of "99% within 2 s" fast (1 hour) or slowly (6 hours) | critical / warning |
| RelicUpstreamErrors | over 20% of a format's upstream requests fail for 15 minutes | warning |
| RelicDBPoolExhausted | every database connection is in use and requests wait, for 10 minutes | warning |
| RelicJobBacklog | the oldest job of a job kind has waited over 30 minutes | warning |
| RelicScanBacklog | the scan backlog grows for an hour, or the vulnerability database is over 3 days old | warning |
| RelicCVEFeedStale | a CVE feed is older than 3 times its refresh interval | info |
| RelicGCFailing | no garbage collection run succeeded in 6 hours | warning |
| RelicReplicationFailing | a repository's last 3 replication runs failed | warning |
| RelicStorageErrors | over 1% of object storage operations fail for 10 minutes | critical |
| RelicContentIntegrity | a read or the storage check found stored content missing or not matching its checksum | critical |
| RelicDiskSpaceLow | under 10% of a single node's data volume is free for 15 minutes | warning |
| RelicServerCertificateExpiring | the certificate a server serves expires within 14 days | warning |

## Runbooks

Every alert in `deploy/observability/prometheus/relic-rules.yaml` links to its
section below.

### RelicDown

No Relic server has been scraped for 5 minutes.

1. Check the pods or containers with `kubectl get pods -l app.kubernetes.io/component=server`
   or `docker compose ps relic-server`.
2. A server that restarts in a loop usually cannot reach PostgreSQL or object
   storage, or cannot apply a migration. Read its last log lines.
3. If the pods are running, check the scrape. Prometheus must be able to reach
   the metrics port (`8091`), and the ServiceMonitor must select the Service.

### RelicHighErrorRate

More than 5% of one API family's requests answered 5xx for 10 minutes.

1. On **Relic / Overview**, use the *5xx ratio* and *Slowest routes* panels to
   find the routes behind the errors. Open an exemplar's trace.
2. Filter the log panel by the trace ID. The `error` field names the cause.
3. Database and object storage errors have their own alerts
   (RelicDBPoolExhausted, RelicStorageErrors). If those fire, start there.

### RelicDownloadLatencySLO

Downloads miss the objective of 99% within 2 seconds. The critical alert means
the error budget burns fast, measured over an hour of data. The warning means it
burns slowly, measured over six hours.

1. On **Relic / Packages and repositories**, check whether the slow downloads
   come from remote repositories (upstream latency) or local ones.
2. On **Relic / Storage and garbage collection**, check object storage
   latency (`get`).
3. On **Relic / Database**, check pool waits and slow queries.

### RelicUpstreamErrors

More than 20% of requests to the upstreams of one format's remote repositories
failed for 15 minutes. Relic still serves cached content.

1. Check that the upstream answers from Relic's network: egress, proxy and DNS.
2. A `401` or `403` answer means the upstream credentials have expired. Update
   them in the remote repository.
3. While an upstream is down, you can set its remote repositories offline.

### RelicDBPoolExhausted

Every database connection of an instance is in use, and requests wait for one.

1. On **Relic / Database**, use *Time spent by query* to find the queries that
   hold connections.
2. `RELIC_DATABASE_STATEMENT_TIMEOUT` cuts long queries. Check PostgreSQL itself
   (locks, I/O) on the CloudNativePG dashboard.
3. Add server replicas, or raise `RELIC_DATABASE_MAX_CONNECTIONS` (default 20
   per process). Replicas × pool size, plus the worker's pool, must stay within
   PostgreSQL's `max_connections`.

### RelicJobBacklog

The oldest available job of a job kind has waited more than 30 minutes.

1. Check that a worker is running (`relic_build_info{component="worker"}`).
2. On **Relic / Jobs and worker**, check which kinds wait and whether their runs
   fail.
3. Long scans occupy the scan queue. If the backlog keeps growing, add worker
   replicas.

### RelicScanBacklog

The scan backlog has grown for an hour, or Grype's vulnerability database is
older than three days. The `cause` label says which.

1. For a backlog, see **Relic / Relic Scan**. Each worker runs at most two scans
   at a time. Add worker replicas, or check the worker logs for scan failures.
2. For an old database: the worker updates it every 12 hours from the Grype
   database listing. This needs outbound access, or an imported archive in
   air-gapped sites. Check the errors of the `scan_db` job on the System page.

### RelicCVEFeedStale

Relic has not read the EPSS or KEV feed for three times its refresh interval.

1. The worker reads both feeds in the hourly `cve_refresh` job. The job's last
   error is on the System page.
2. Air-gapped sites point `RELIC_CVE_EPSS_URL` and `RELIC_CVE_KEV_URL` at a
   generic repository. Update the files there.

### RelicGCFailing

Every garbage collection run in the last six hours failed, so unreferenced
content is not reclaimed.

1. The error of the `gc` job is on the System page and in the worker's logs.
2. The usual cause is object storage refusing deletes because of credentials or
   the bucket policy. See RelicStorageErrors.

### RelicReplicationFailing

A repository's last three push replication runs failed.

1. The last error is on the repository's replication page.
2. Check the target's URL and credentials, and that the worker can reach the
   target.

### RelicStorageErrors

More than 1% of object storage operations failed for 10 minutes. Uploads and
downloads fail along with them.

1. On **Relic / Storage and garbage collection**, check which operations
   fail.
2. Check the S3 endpoint (the SeaweedFS pods, or the provider's status), the
   credentials, and free space.

### RelicContentIntegrity

A read or the storage check found content missing from object storage, or
content that does not match its size or checksum. Relic refuses to serve such
content: downloads of that file fail until the content is restored.

1. For a read, the log line `stored content is missing` or `stored content does
   not match its checksum` names the SHA-256, the repository and the path.
2. Run the storage check and print its report, which lists each missing or
   damaged object by SHA-256:

   ```bash
   relic storage check --wait
   ```

3. Upload the file again, with any client. Relic replaces a missing or damaged
   object with the uploaded one.
4. If many objects are affected, check the object store: a lost volume, a
   bucket lifecycle rule that deletes from `artifacts`, or a restore from an
   older backup.

### RelicDiskSpaceLow

Under 10% of a single node's volume is free. The volume holds the SQLite
database (`volume="database"`) or the filesystem object store
(`volume="object_storage"`). When the volume fills, writes fail.

1. `relic_db_sqlite_file_bytes` is the database's share of the volume. The rest
   is content.
2. Empty the trash and lower `RELIC_TRASH_RETENTION`. Garbage collection then
   reclaims content that no item references, after
   `RELIC_GARBAGE_COLLECTION_GRACE_PERIOD`.
3. Grow the volume. In Helm, set `data.size` on a storage class that allows
   expansion. You can also move to S3 and PostgreSQL with
   `relic server database copy`.

### RelicServerCertificateExpiring

The certificate a server serves expires within 14 days. `source="operator"` is
a certificate you provide with `RELIC_TLS_CERTIFICATE_FILE` and
`RELIC_TLS_KEY_FILE`. `source="generated"` is one Relic issued from its own
certificate authority.

1. For your own certificate, renew it and replace the files. The server reads
   them again when they change, without a restart.
2. With cert-manager, check the Certificate's status and the issuer's events.
3. A generated certificate is renewed 30 days before it expires. If this alert
   fires for one, the server cannot write its TLS directory
   (`RELIC_TLS_DIRECTORY`): check the logs and the directory's permissions.
