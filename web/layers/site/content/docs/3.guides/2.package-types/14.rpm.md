---
title: RPM
description: RPM repositories for dnf and yum, with signed repodata.
---

An RPM repository serves the repodata dnf and yum read, generated from the
packages it holds: `repomd.xml`, signed with the repository's key pair, and
the primary, filelists and other metadata it lists.

Upload a package, to any folder of a local repository:

```bash
relic artifact upload hello-1.0-1.x86_64.rpm rpm-local/el9/hello-1.0-1.x86_64.rpm
```

As root, write `/etc/yum.repos.d/relic-rpm-virtual.repo` with your token, and the
repository's public key when it names its own signing key:

```bash
relic package setup dnf rpm-virtual --write
```

dnf then installs through Relic:

```bash
dnf install hello
```

To configure dnf by hand, save the repository's public key:

```bash
curl -fsSL -u <you>:<token> -o /etc/pki/rpm-gpg/RPM-GPG-KEY-relic https://relic.example.com/rpm/rpm-virtual/repodata/repomd.xml.key
```

Then add the repository, in `/etc/yum.repos.d/relic.repo`:

```ini
[relic]
name=Relic
baseurl=https://relic.example.com/rpm/rpm-virtual
username=<you>
password=<token>
gpgcheck=0
repo_gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-relic
```

The metadata depth and the signing key are repository settings, `metadataDepth` and
`signingKey`, set in the repository form (**Metadata depth**, **Signing key**) or in
YAML with `relic apply -f`:

```yaml
apiVersion: relic.build/v1
kind: Repository
metadata:
  name: rpm-local
spec:
  class: local
  format: rpm
  metadataDepth: 1
  signingKey: rpm-signing
```

- `repo_gpgcheck=1` makes dnf check `repomd.xml.asc`, the signature Relic
  makes with the repository's key pair. `gpgcheck` checks the packages' own
  signatures; keep it on for signed packages, with their vendor's key.
- `signingKey` names a key pair. Relic creates it, as an OpenPGP key pair, the
  first time it signs with it; key pairs cannot be imported. Without
  `signingKey`, Relic signs with its default key pair, `relic-gpg`.
  `relic api key-pairs` lists the key pairs.
- A remote RPM repository proxies an upstream one, for example
  `https://dl.rockylinux.org/pub/rocky/9/BaseOS/x86_64/os`. A virtual repository
  merges its members' repodata (a remote member's upstream repodata included)
  and signs the result.
- The metadata depth (`metadataDepth`) sets where repodata is: 0, the default,
  indexes the whole repository at `repodata/`; 1 indexes each top folder, for
  example `el9/repodata/` and `el10/repodata/`, so one repository can serve
  several releases.
- Through the JFrog® Artifactory® API, the package type `yum` is an RPM
  repository that reports `yum` back, `yumRootDepth` is the metadata depth, and
  `primaryKeyPairRef` is the signing key.
