---
title: RPM
description: RPM repositories for dnf and yum, with repodata generated and signed by Relic.
---

Relic generates an RPM repository's repodata from its packages, with `repomd.xml` signed by the repository's key pair.

Upload a package to any folder of a local repository:

```bash
relic artifact upload hello-1.0-1.x86_64.rpm rpm-local/el9/hello-1.0-1.x86_64.rpm
```

As root, this command writes `/etc/yum.repos.d/relic-rpm-virtual.repo` with your token, and
the repository's public key:

```bash
relic package setup dnf rpm-virtual --write
```

Install through Relic:

```bash
dnf install hello
```

To configure dnf by hand, save the public key:

```bash
curl -fsSL -u <you>:<token> -o /etc/pki/rpm-gpg/RPM-GPG-KEY-relic https://relic.example.com/rpm/rpm-virtual/repodata/repomd.xml.key
```

Then add `/etc/yum.repos.d/relic.repo`:

```ini
[relic]
name=Relic
baseurl=https://relic.example.com/rpm/rpm-virtual
username=<you>
password=<token>
gpgcheck=0
repo_gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-relic
```

`metadataDepth` (**Metadata depth**) and `signingKey` (**Signing key**) are repository settings:

```yaml
apiVersion: relic.build/v1
kind: Repository
metadata:
  name: rpm-local
spec:
  class: local
  format: rpm
  metadataDepth: 1
  signingKey: rpm-signing
```

- `repo_gpgcheck=1` checks `repomd.xml.asc`, Relic's signature. `gpgcheck` checks the
  packages' own signatures; enable it for signed packages, with their vendor's key.
- `signingKey` names an OpenPGP key pair, created on first use; key pairs cannot be
  imported. The default is `relic-gpg`. `secondarySigningKey` names a second key pair whose
  public key `repomd.xml.key` also holds, so the key can be replaced
  ([Signing keys](/docs/guides/operations#signing-keys)). `relic api key-pairs` lists them.
- `metadataDepth` 0 (default) indexes the whole repository at `repodata/`; 1 indexes each top
  folder (`el9/repodata/`, `el10/repodata/`), so one repository serves several releases.
- A remote proxies an upstream repository, such as
  `https://dl.rockylinux.org/pub/rocky/9/BaseOS/x86_64/os`. A virtual repository merges its
  members' repodata, remote ones included, and signs the result.
- A virtual repository serves repodata at its own `metadataDepth`, from the same folder of
  each member: with `metadataDepth: 1`, `el9/repodata/` lists its members' `el9/` packages.
  With 0, it lists all of its members' packages.
- A virtual repository's repodata is rebuilt at most every 30 seconds. A request after that
  gets the last built copy while one rebuild runs, and waits for the rebuild when the copy is
  older than 10 minutes.
- Through the JFrog® Artifactory® API, package type `yum` is an RPM repository,
  `yumRootDepth` is the metadata depth, `primaryKeyPairRef` the signing key and
  `secondaryKeyPairRef` the secondary signing key.
