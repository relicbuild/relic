---
title: npm, yarn and pnpm
description: Resolve and publish npm packages.
---

Create an npm repository first. It can be local, a remote of `https://registry.npmjs.org`,
or a virtual repository over both. Then configure npm for it.

This command writes the registry URL and a token for it to `~/.npmrc`:

```bash
relic package setup npm npm --write
```

npm then installs packages from the repository:

```bash
npm install
```

It also publishes to it:

```bash
npm publish
```

`relic package setup pnpm` and `relic package setup yarn` do the same for pnpm and Yarn.

To configure npm by hand, add these lines to `.npmrc`:

```ini
registry=https://relic.example.com/npm/npm/
//relic.example.com/npm/npm/:_authToken=<token>
```

`npm login --registry https://relic.example.com/npm/npm/` writes the token for you. Yarn (berry)
uses the same token in `.yarnrc.yml`:

```yaml
npmRegistryServer: "https://relic.example.com/npm/npm"
npmAlwaysAuth: true
npmAuthToken: "<token>"
```

pnpm reads `.npmrc`. If Relic's certificate comes from a private CA, such as the one Relic
generates ([TLS](/docs/installation/configuration#tls)), set `cafile` in `.npmrc` to the CA
certificate, or set `NODE_EXTRA_CA_CERTS` to it. Node does not read the system certificate store.

- `npm dist-tag`, `npm deprecate` and `npm search` work.
- `npm audit` uses the advisory database of the repository's npm remote
  (registry.npmjs.org). A repository without a remote answers `npm audit` with 503.
  npm then reports that the audit could not run. It does not report a clean result.
- In the UI, a tarball's page shows its `package.json`, with its dependencies and license,
  and an install command.
