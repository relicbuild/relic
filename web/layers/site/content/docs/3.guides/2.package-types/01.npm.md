---
title: npm, yarn and pnpm
description: Install and publish npm packages with npm, Yarn and pnpm through an npm repository.
---

This command writes the registry URL and a token to `~/.npmrc`:

```bash
relic package setup npm npm --write
```

Install packages:

```bash
npm install
```

Publish a package:

```bash
npm publish
```

`relic package setup pnpm` and `relic package setup yarn` configure pnpm and Yarn.

To configure npm and pnpm by hand, add to `.npmrc` (or run `npm login --registry https://relic.example.com/npm/npm/`):

```ini
registry=https://relic.example.com/npm/npm/
//relic.example.com/npm/npm/:_authToken=<token>
```

Yarn 1 reads `.npmrc` too, but sends the token for unscoped packages only when `always-auth` is
set for the registry. `relic package setup yarn` adds this line, which npm 11 warns it does not
know:

```ini
//relic.example.com/npm/npm/:always-auth=true
```

For Yarn 2 and later, add to `.yarnrc.yml`:

```yaml
npmRegistryServer: "https://relic.example.com/npm/npm"
npmAlwaysAuth: true
npmAuthToken: "<token>"
```

For a private CA ([TLS](/docs/installation/configuration#tls)), set `cafile` in `.npmrc` or
`NODE_EXTRA_CA_CERTS`; Node ignores the system certificate store.

- A remote repository caches each packument for the metadata cache period (2 hours by
  default) and serves the cached one while the upstream is down or the repository is offline.
- `npm dist-tag`, `npm deprecate` and `npm search` work.
- `npm audit` asks the upstream of the repository's npm remote. Without a remote the server
  answers `503`, and npm reports that the audit could not run.
- `npm audit signatures` gets the registry's signing keys (`-/npm/v1/keys`) and a version's
  attestations (`-/npm/v1/attestations/<name>@<version>`) from the upstream of the
  repository's npm remote. Without an online remote both answer `404`. Packages published to
  Relic carry no registry signature.
- A tarball's **npm** tab shows its `package.json`, dependencies, license and install command.
