A Nix repository is a binary cache. It can be local, a remote of
`https://cache.nixos.org`, or a virtual repository over both.

This command adds the repository to `~/.config/nix/nix.conf` as an extra substituter,
and writes your credentials to `~/.netrc`:

```bash
relic package setup nix nix --write
```

Nix then fetches store paths from the repository instead of building them, when it
trusts their signatures (see [Signatures](#signatures)).

Upload a store path, with its closure, to a local repository:

```bash
nix copy --to https://relic.example.com/nix/nix-local ./result
```

To configure Nix by hand, add the repository to `~/.config/nix/nix.conf`:

```ini
extra-substituters = https://relic.example.com/nix/nix
netrc-file = /home/<you>/.netrc
```

Keep the credentials in `~/.netrc`:

```bash
printf 'machine relic.example.com\nlogin <you>\npassword <token>\n' >> ~/.netrc
```

## Signatures

Relic does not sign store paths. A path keeps the signatures `nix copy` uploaded with
it, and Nix substitutes only paths signed by a key in `trusted-public-keys`. Paths
from cache.nixos.org keep its signature.

Make a key pair for your own paths:

```bash
nix-store --generate-binary-cache-key relic.example.com-1 cache-key.sec cache-key.pub
```

Sign a path and its closure before you copy it:

```bash
nix store sign --key-file cache-key.sec --recursive ./result
```

Trust the public key, the content of `cache-key.pub`, in `nix.conf`:

```ini
extra-trusted-public-keys = relic.example.com-1:<public key>
```

For a private cache of unsigned paths, `require-sigs = false` turns signature checks
off, for every substituter.

- On a multi-user installation, the Nix daemon downloads the paths, so the
  substituter, `netrc-file` and the public key belong in `/etc/nix/nix.conf`.
- A remote repository caches what it fetches from its upstream. A virtual repository
  resolves its members in order, and `nix copy --to` a virtual repository stores in
  its default deployment repository.
- Relic stores each path under `binary-cache/<hash>/`: its `.narinfo` and its NAR.
- Channels (`nix-channel`) are not served.
- The JFrog® CLI's `jf nix` works with `/artifactory/api/nix/<repo>`.
