---
title: Go
description: Use Relic as a GOPROXY and publish modules.
---

This command sets `GOPROXY` and `GONOSUMDB` and writes your credentials to `~/.netrc`:

```bash
relic package setup go go --private 'corp.example.com/*' --write
```

The go command then downloads modules through Relic:

```bash
go build ./...
```

This command publishes a module version. It uploads the module zip, `go.mod` and `.info`:

```bash
relic package publish go go-local v1.2.3 --dir .
```

To configure Go by hand, set the proxy. Set `GONOSUMDB` to your private module prefixes, for
example `corp.example.com`:

```bash
export GOPROXY=https://relic.example.com/go/go
export GONOSUMDB=<your private module prefixes>
```

Keep the credentials in `~/.netrc`:

```bash
printf 'machine relic.example.com\nlogin <you>\npassword <token>\n' >> ~/.netrc
```

If Relic's certificate comes from a private CA, such as the one Relic generates
([TLS](/docs/installation/configuration#tls)), point the go command at the CA certificate with
`SSL_CERT_FILE`.

A remote repository pointing at `https://proxy.golang.org` caches public modules.

Checksum verification stays on. The go command asks its proxy for the checksum database
(`sum.golang.org`). Relic serves it when the repository is a Go remote, or a virtual
repository with a Go remote. Builds then verify `go.sum` without internet access.
Private modules are not in the public database, so list them in `GONOSUMDB`.
