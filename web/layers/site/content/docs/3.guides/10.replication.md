---
title: Replication
description: Copy a repository to or from another server, or keep two servers' repositories alike.
---

A replication links a local repository to one on another server, run by the
worker on a schedule.

| Direction | A run |
| --- | --- |
| `push` | copies files the target lacks or holds another version of; with `syncDeletes`, deletes the target's files this repository no longer has |
| `pull` | copies the target's files this repository lacks or holds another version of, verifying checksums; with `syncDeletes`, deletes files the target no longer has |
| `federated` | pulls, then pushes, so both end up alike |

A federated replication also runs on each deploy and delete; the newest write or
delete wins. Configure it on both servers, each pointing at the other. With
`syncProperties`, pushes copy properties. With `onChange`, a push replication
also runs after each change.

The other server, a Relic or an Artifactory, is reached through the JFrog®
Artifactory® REST API. For a private address, set
`RELIC_UPSTREAM_ALLOW_PRIVATE_ADDRESSES=true` on the server and the worker.

```yaml
apiVersion: relic.build/v1
kind: Replication
metadata: {name: libs-release}
spec:
  direction: federated
  targetUrl: https://relic-eu.example.com/artifactory/libs-release
  username: replicator
  password: change-me
  schedule: "*/15 * * * *"
  enabled: true
```

Apply it:

```bash
relic apply -f replication.yaml
```

Run it now:

```bash
relic replication run libs-release
```
