title: AI agents
description: Give coding agents read-only access to Relic over the Model Context Protocol.
---

Relic serves the Model Context Protocol (MCP), so coding agents can search
artifacts, read their scans and ask why a download is blocked. Every tool
calls the Relic API as you, so an agent sees only what you may read. No tool
changes anything.

| Tool | Answers |
| --- | --- |
| `search_artifacts` | files whose name contains a text, in the repositories you may read |
| `artifact_details` | a file's size, checksums, properties, builds and scan |
| `artifact_findings` | the vulnerabilities, malicious packages, secrets and misconfigurations found in a file |
| `explain_download` | whether a download is blocked, and by which policy or by the quarantine |
| `list_repositories` | the repositories, with their class and format |
| `repository_setup` | the URLs a package manager or container client uses for a repository |
| `package_allowed` | whether a package version may be added as a dependency |

## Over standard input and output

`relic mcp` runs an MCP server for an agent that starts it as a subprocess,
with the credentials of the current `relic` context. Sign in first:

```bash
relic auth login https://relic.example.com
```

Then register the command with the agent. For example, in a project's
`.mcp.json`:

```json
{
  "mcpServers": {
    "relic": {"command": "relic", "args": ["mcp"]}
  }
}
```

## Over HTTP

The server serves MCP over streamable HTTP at `/mcp`. It needs an access
token, sent as `Authorization: Bearer <token>`; browser sessions are not
accepted. Create a token for the agent:

```bash
relic auth token create --description "coding agent" --expires-days 30
```

Then point the agent at the endpoint:

```json
{
  "mcpServers": {
    "relic": {
      "type": "http",
      "url": "https://relic.example.com/mcp",
      "headers": {"Authorization": "Bearer ${RELIC_TOKEN}"}
    }
  }
}
```

## Routing an agent's dependencies

Point a project's package manager at Relic and tell the agents working in it
to ask Relic before adding a dependency. In the project directory, run:

```bash
relic package setup npm npm-virtual --agent
```

This writes the client's configuration to your user files, as `--write` does
(the token never goes into the project), adds a section to the project's
`AGENTS.md` telling coding agents to resolve dependencies only through the
repository and to ask `package_allowed` first, and registers `relic mcp` in
the project's `.mcp.json`. Both files keep what else they hold, and running
the command again replaces the section.

`package_allowed` refuses a version when:

- the malicious package catalog lists it;
- the repository's npm or PyPI metadata leaves it out: it is cooling down,
  quarantined, blocked or absent;
- a stored finding of the package, or its end of life, deprecation or lack
  of maintenance, violates a rule, failing builds or blocking downloads, of
  a watch covering the repository. Ignore rules apply as they do to
  downloads.

A package URL whose type the repository's format cannot hold, such as a
`pkg:pypi` URL checked against an npm repository, is an error rather than an
answer. A generic repository takes any type.

The answer also lists the version's operational risks, from the server's
end-of-life data, even when no policy refuses them, so an agent can prefer a
maintained release.

The same check is a command, which exits with status 1 when the version is
refused:

```bash
relic package check pkg:npm/lodash@4.17.21 --repository npm-virtual
```

## MCP server and skill registries

Two repository formats hold what agents install:

- `mcp`: MCP server definitions, `server.json` files in the MCP registry
  format. MCP clients read the approved ones through the registry API at
  `/api/mcp/<repository>/v0/servers`.
- `skills`: agent skill bundles, zip files with a `SKILL.md` whose front
  matter gives the skill's `name` and `description`.

An entry is listed and served only once an administrator approves its
content: until then, a download of its file is refused through every route
(the files API, the Artifactory®-compatible API), and so is a copy or move of it,
except to administrators and viewers, who review it. Uploading new content to an approved path needs a new
approval. Skill bundles
go through Relic Scan like any zip file, so secrets and malicious packages in
them are found. **Agent registry** in the UI lists the entries and approves
them.

Upload a server definition:

```bash
relic artifact upload server.json mcp-servers/weather/1.1.0/server.json
```

List the entries, approved or not:

```bash
relic registry list mcp-servers
```

Approve one:

```bash
relic registry approve mcp-servers/weather/1.1.0/server.json
```

Point an MCP client's registry at Relic:

```text
https://relic.example.com/api/mcp/mcp-servers
```
