## Classes

| Class | What it does |
| --- | --- |
| Local | Stores what you deploy. |
| Remote | Proxies an upstream registry and caches what it fetches. |
| Virtual | Gives several repositories one URL. It resolves from its members in order and deploys to its default repository. |

Create a repository in **Repositories → New repository**. You can also declare it in YAML and run
`relic apply -f` (see [Resources](/docs/cli/resources)). Relic stores each file content once
per SHA-256, so copies and moves use no extra storage.

## Remote repositories

A remote repository fetches a file from its upstream the first time a client
asks for it, then serves it from the cache. Metadata (npm packuments, PyPI
pages, `maven-metadata.xml`) is fetched again after the metadata cache period.

- **Checksums.** Relic checks a fetched file against the checksum its upstream
  publishes: the `X-Checksum-*` headers, a Maven `.sha1` file, npm's
  `dist.shasum`, or a PyPI `#sha256=` link. A file that does not match is never
  stored, and the client gets `502`.
- **Missing files.** A file the upstream does not have (`404` or `410`) is not
  asked for again for 30 minutes. Set **Remember upstream misses**
  (`missedRetrievalCachePeriodSecs` in the JFrog® Artifactory®-compatible API) to
  change this period, or to 0 to ask every time.
- **Failures.** An upstream that fails (`429`, `502`, `503`, `504`, a dropped
  connection) is tried three times within one budget, honouring `Retry-After`.
  A name that does not resolve or a certificate that does not verify is not
  retried. The client gets `502`, and the failure is not remembered.
  Relic's own failures answer `500` with `Cache-Control: no-store`.
- **Cooldown.** Most malicious packages are found and removed within days of
  being published. Set **Cooldown (days)** to hide npm and PyPI versions
  published upstream more recently than that, and to refuse their files with
  `403`. npm's `latest` tag moves to the newest version old enough, so
  `npm install` picks it. Relic reads the publish time from the npm packument
  and from PyPI's JSON simple index. Other formats ignore the setting.
- **Version selection.** npm packuments and PyPI pages served through a
  remote repository leave out the versions a client must not install: those
  the malicious package catalog lists, and cached ones that are quarantined or
  blocked by a watch. npm's `latest` tag moves to the newest version left, so
  `npm install` and `pip install` pick an allowed version instead of failing.
- **One fetch.** When several clients, or several Relic replicas, ask for the
  same file at once, Relic fetches it once and the others wait for the cached
  copy.

In YAML, a remote repository's settings go under `remote`:

```yaml
apiVersion: relic.build/v1
kind: Repository
metadata:
  name: npm-remote
spec:
  class: remote
  format: npm
  remote:
    url: https://registry.npmjs.org
    cooldownDays: 7
    quarantine: true
```

| Form field | `remote` field | Effect |
| --- | --- | --- |
| **Upstream URL** | `url` | The upstream registry. |
| **Upstream username**, **Upstream password or token** | `username`, `password` | Credentials for the upstream. Relic never shows the password again, and an update without one keeps it. |
| **Package index URL** | `indexUrl` | The upstream's package index, when it is not at `url` (the PyPI registry, a NuGet v3 feed). |
| **Metadata cache (seconds)** | `cachePeriodSeconds` | How long metadata is served before Relic asks the upstream again. 0 uses the default, 2 hours. |
| **Upstream timeout (ms)** | `timeoutMilliseconds` | How long Relic waits for the upstream. 0 uses the default, 15 seconds. |
| **Remember upstream misses (seconds)** | `missedRetrievalCachePeriodSeconds` | See *Missing files* above. 1800 when unset. |
| **Cooldown (days)** | `cooldownDays` | See *Cooldown* above. |
| **Quarantine** | `quarantine` | Hold what the repository caches until Relic Scan has scanned it and found it not malicious, or an administrator releases it. |
| **Offline** | `offline` | Serve only what is cached, and never contact the upstream. |
| **Do not cache** | `disableCache` | Serve upstream files without keeping them. |

## Virtual repositories

In YAML, a virtual repository's settings go under `virtual`:

```yaml
apiVersion: relic.build/v1
kind: Repository
metadata:
  name: npm
spec:
  class: virtual
  format: npm
  virtual:
    members: [npm-local, npm-remote]
    deployTo: npm-local
    localOnlyPatterns: ["@acme/*"]
```

| Form field | `virtual` field | Effect |
| --- | --- | --- |
| **Members, in resolution order** | `members` | The repositories it resolves from, in order. Each must exist; deleting a repository removes it from the virtual repositories it belongs to. |
| **Default deployment repository** | `deployTo` | The local member that receives uploads. Without one, uploads are refused. |
| **Local-only names** | `localOnlyPatterns` | See [Dependency confusion](#dependency-confusion). |

## Dependency confusion

An attacker who publishes a public package with the name of an internal one can
get it installed through a virtual repository that also proxies the public
registry. List your internal names under **Local-only names** on the virtual
repository (`localOnlyPatterns`), as Ant patterns on package names or paths:
`@acme/*` for an npm scope, `com/acme` for a Maven group, `acme-*` for PyPI
projects, `github.com/acme/**` for Go modules. Those names resolve only from
the virtual repository's local members, and Relic never asks a remote member
for them, nor a remote inside a nested virtual repository. Patterns are
case-sensitive, except in a PyPI repository, where `Acme_*` and `acme-*` name
the same projects, as PyPI normalizes names.

## Client URLs

A client URL is the format's path followed by the repository name. `relic package setup <client> <repository>`
writes this URL into the client's configuration. **Set me up** in the UI shows the configuration for npm,
Maven, Gradle, PyPI, Go, NuGet, Docker, OCI, Helm, Helm OCI and RPM repositories, and `curl` commands for
the files of every repository.

| Format | URL |
| --- | --- |
| npm, yarn, pnpm | `https://relic.example.com/npm/<repo>/` |
| PyPI | `https://relic.example.com/pypi/<repo>/simple` |
| Maven, Gradle | `https://relic.example.com/maven/<repo>`, `https://relic.example.com/gradle/<repo>` |
| Go | `https://relic.example.com/go/<repo>` |
| NuGet | `https://relic.example.com/nuget/<repo>/index.json` (V2: `https://relic.example.com/nuget/<repo>`) |
| RubyGems | `https://relic.example.com/gems/<repo>/` |
| Cargo | `sparse+https://relic.example.com/cargo/<repo>/index/` |
| Conan | `https://relic.example.com/conan/<repo>` |
| Helm | `https://relic.example.com/helm/<repo>` |
| Terraform | `https://relic.example.com/terraform/<repo>/providers/`; modules as `relic.example.com/<repo>__<namespace>/<name>/<provider>` |
| Hugging Face | `HF_ENDPOINT=https://relic.example.com/huggingface/<repo>` |
| Nix | `https://relic.example.com/nix/<repo>` |
| Debian, Alpine | `https://relic.example.com/debian/<repo>`, `https://relic.example.com/alpine/<repo>` |
| RPM | `https://relic.example.com/rpm/<repo>` |
| Docker, OCI, Helm OCI | `relic.example.com/<repo>/<image>` |

## Browsing

The repository tree shows every file and folder you have read access to. **Find by name**
searches the whole repository. Selecting an item shows these tabs:

| Tab | Shows |
| --- | --- |
| **General** | Path, URL, checksums and downloads. |
| **Properties** | Properties, editable. |
| **Security**, **SBOM** | Scan results. |
| **Builds** | Builds that produced or used the file. |
| **Permissions** | For administrators: the users and groups that may read, annotate, deploy, delete or manage the item, and the permissions that grant it. |
| **Archive** | Entries inside zips, JARs and tarballs. |
| **View** | Text files. |
| Package tabs | A tab for the package format, for npm, PyPI, Helm, Docker and Maven packages. |

The selected tab is part of the URL, so you can link to it.

## Limits

A local repository can limit what it accepts. Set the limits in the
repository form, the Relic API or `relic apply`:

```yaml
apiVersion: relic.build/v1
kind: Repository
metadata:
  name: libs-local
spec:
  class: local
  format: maven
  maxUploadSize: 1073741824     # 1 GiB
  maxStorage: 536870912000      # 500 GiB
```

| Setting | Effect |
| --- | --- |
| `maxUploadSize` | The largest file, in bytes. A larger upload fails with `413`. `RELIC_MAX_UPLOAD_SIZE` sets a limit for every repository; the lower one applies. |
| `immutable` | Refuse replacing a file with other content, which also stops container tags from moving. Uploading the same content again succeeds. |
| `maxStorage` | The quota, in bytes: the most the repository's files may take together. A deploy, copy or move past it fails with `413`. A file stored once but present in two repositories counts in both. The repository's current use is `usedBytes` in `relic get repository`. |

## Cleanup policies

A cleanup policy moves old or unused items of local repositories to the trash
can. The worker runs every enabled policy once a day. Define policies on the
**Cleanup policies** page or with `relic apply`:

```yaml
apiVersion: relic.build/v1
kind: CleanupPolicy
metadata:
  name: old-app-versions
spec:
  enabled: true
  repositories: [libs-local]
  pathPattern: org/app/*
  olderThanDays: 90
  keepLatest: 5
```

| Setting | Effect |
| --- | --- |
| `repositories` | The local repositories the policy covers. |
| `pathPattern` | An Ant pattern of the items to consider: `org/app/*` takes the version folders of `org/app`, `**/*.tgz` every tarball. Empty is `**`. A matched folder moves with its contents. |
| `olderThanDays` | Only items created more than this many days ago. |
| `notDownloadedDays` | Only items not downloaded for this many days, or never downloaded and older than that. |
| `keepLatest` | Keep this many of the newest matched items in each folder, whatever their age. |

A policy needs at least one of the last three settings. Files Relic writes
itself, such as `maven-metadata.xml`, are never selected. Deleting a
repository removes it from the policies that name it; a policy left without
repositories is disabled.

See what a policy would select, without moving anything:

```bash
relic cleanup preview old-app-versions
```

Run it now instead of waiting for the daily run:

```bash
relic cleanup run old-app-versions
```

Items stay in the trash can for its retention period, so a mistake can be
undone from there.

## Legal holds

A legal hold protects an item, or a folder with everything under it: it
cannot be deleted, moved, overwritten or selected by a cleanup policy, and its
repository cannot be deleted. Administrators place and release holds.

Place a hold:

```bash
relic hold add libs-local/org/app/1.4.0 --reason "audit 2026-14"
```

List the holds:

```bash
relic hold list
```

Release a hold:

```bash
relic hold remove libs-local/org/app/1.4.0
```

## Trash can

Deleting an item with `relic artifact rm`, the Relic API or the UI moves it into the
`auto-trashcan` repository. It stays there for 14 days. `RELIC_TRASH_RETENTION` sets this period.
Administrators restore or purge items in **Administration → Trash can** or through
the Relic API.

This command lists the newest 50 entries in the trash can, with their paths
and how many entries there are:

```bash
relic api trash
```

This command lists the next 50:

```bash
relic api 'trash?page=2'
```

This command restores one item:

```bash
relic api /api/relic.v1.TrashService/RestoreTrash -d '{"path": "libs-local/org/app/1.0/app-1.0.jar"}'
```

This command empties the trash can:

```bash
relic api /api/relic.v1.TrashService/EmptyTrash -d '{}'
```

Deleting a whole repository is permanent.

## Replication

Relic can push a local repository to a repository on another server, pull from one, or keep the
two alike (federated). A replication runs on a schedule. A push replication with `onChange`, and a
federated one, also run after each change. Configure replication in **Administration → Replication**,
or declare a `Replication` resource and run `relic apply` (see [Replication](/docs/guides/replication)).
