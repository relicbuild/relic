---
title: Webhooks
description: Send Relic's events to CI, chat and other services.
---

A webhook subscribes a URL to event types. When an event happens, Relic
queues a delivery for every enabled webhook subscribed to its type, and the
worker posts it. A delivery that fails (no answer, or a status other than
2xx) is retried with a doubling backoff, from 30 seconds up to 32 minutes,
8 attempts in all. Deliveries are kept for 30 days. A disabled webhook
receives nothing: its pending deliveries fail instead of being sent.

Relic delivers only to public addresses, not to loopback, private or
link-local ones. To reach a service on the company network, set
`RELIC_WEBHOOK_ALLOW_PRIVATE_ADDRESSES=true` on the server and the worker.

| Event | When |
| --- | --- |
| `artifact.deployed` | a file is deployed to a local repository |
| `artifact.deleted` | a file or folder is deleted |
| `scan.finished` | Relic Scan finished scanning a file's content |
| `download.blocked` | a policy or the quarantine blocked a download |
| `release.promoted` | a release version was promoted to an environment |
| `quarantine.released`, `quarantine.rejected` | an administrator decided on a quarantined file |

`*` subscribes a webhook to every event type.

## Payload

With the `json` format, the body is the event:

```json
{
  "id": "0192f7a0-5d1e-7c3a-9b2f-6e4d8a1c0b7e",
  "type": "artifact.deployed",
  "subject": "libs-release/org/acme/app/1.0/app-1.0.jar",
  "actor": "ci-bot",
  "time": "2026-10-05T12:00:00Z",
  "data": {"repository": "libs-release", "path": "org/acme/app/1.0/app-1.0.jar", "sha256": "…", "size": 1024}
}
```

Each request carries `X-Relic-Event` (the type) and `X-Relic-Delivery` (the
id). The `slack` format posts a Slack message, `{"text": …}`, to a Slack
incoming webhook URL.

## Signatures

Give a webhook a secret and Relic signs each body: `X-Relic-Signature` is
`sha256=` followed by the hex HMAC-SHA256 of the body under the secret.
Compare it with your own HMAC of the raw body, in constant time. The secret is
stored sealed and never shown again.

## Managing webhooks

**Administration → Webhooks** adds, edits and pings webhooks, and lists each
one's deliveries. Webhooks are also `relic.build/v1` resources:

```yaml
apiVersion: relic.build/v1
kind: Webhook
metadata: {name: ci-notify}
spec:
  url: https://ci.example.com/hooks/relic
  events: [artifact.deployed, release.promoted]
  format: json
  enabled: true
  secret: change-me
```

Apply the file:

```bash
relic apply -f webhooks.yaml
```

Queue a `webhook.ping` event, to test the receiver:

```bash
relic webhook ping ci-notify
```

List the latest deliveries:

```bash
relic webhook deliveries ci-notify
```
