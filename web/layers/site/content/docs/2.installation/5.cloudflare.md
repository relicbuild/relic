title: Cloudflare
description: Run Relic in a Cloudflare Container behind a Worker, with R2 for the content and your own PostgreSQL for the metadata.
---

`deploy/cloudflare` in the repository holds a Worker and a container
definition. The Worker receives every request for your domain and passes it to
one Relic container. Relic keeps the content in R2. The metadata goes to a
PostgreSQL database that you run elsewhere, for example Neon, Supabase, Amazon
RDS or your own server.

## Limits

- **The container's disk is wiped at every start.** SQLite and the filesystem
  store would lose their data, so this setup needs PostgreSQL and R2. Relic
  downloads the Grype vulnerability database again after each start.
- **Cloudflare limits the size of a request body by plan.** The limit is
  100 MB on Free and Pro, and 200 MB on Business. Enterprise accounts can raise
  it. A larger upload fails with `413`. Docker sends each image layer in one
  request, so a push with a larger layer fails.
- **One container runs Relic.** It runs the server and the background jobs in
  one process (`relic server start --worker`). The instance type is
  `standard-2`: 1 vCPU, 6 GiB of memory and 12 GB of disk.
- **A cron trigger keeps the container awake.** The Worker calls Relic every
  five minutes, so scans, garbage collection and replication keep running.
  Cloudflare bills the container for the time it runs. If you remove the
  trigger, the container sleeps after 15 minutes without requests. Background
  jobs then stop, and the next request waits for the container to start.

## Before you start

You need:

- a Cloudflare account on the Workers Paid plan, which Containers require
- Docker running on your machine, because Wrangler builds the image there
- Node.js 24 and pnpm
- a PostgreSQL database that accepts TLS connections from the internet

## Create the R2 buckets

Create the two buckets, their lifecycle rules and an API token as described in
[Cloudflare R2](/docs/installation/storage/cloudflare-r2). Keep the token's
access key ID and secret access key for the next step.

## Configure

Run the commands on this page in `deploy/cloudflare`. Install the Worker's
dependencies:

```bash
pnpm install
```

Edit `deploy/cloudflare/wrangler.jsonc`:

- In `vars`, replace `<account-id>` in `RELIC_OBJECT_STORAGE_ENDPOINT` with
  your Cloudflare account ID. Change the bucket names if yours differ.
- To serve Relic on your own domain, add a route:
  `"routes": [{ "pattern": "relic.example.com", "custom_domain": true }]`.
  Without one, the Worker answers on its `workers.dev` address.

The container runs the release that `RELIC_VERSION` names in the container's
`image_vars`, `latest` by default. To pin one, set it to the release you want,
for example `vX.Y.Z`.

The Worker passes every variable and secret whose name starts with `RELIC_` to
the container. Any setting from [Configuration](/docs/installation/configuration)
works this way. Store the secret ones with `wrangler secret put`, which asks for
the value.

Store the database URL, for example
`postgres://relic:<password>@db.example.com:5432/relic?sslmode=require`:

```bash
pnpm exec wrangler secret put RELIC_DATABASE_URL
```

Store the R2 access key ID:

```bash
pnpm exec wrangler secret put RELIC_OBJECT_STORAGE_ACCESS_KEY
```

Store the R2 secret access key:

```bash
pnpm exec wrangler secret put RELIC_OBJECT_STORAGE_SECRET_KEY
```

Store the encryption key, the output of `openssl rand -base64 32`:

```bash
pnpm exec wrangler secret put RELIC_ENCRYPTION_KEY
```

Store the password of the `admin` user:

```bash
pnpm exec wrangler secret put RELIC_ADMIN_PASSWORD
```

Keep a copy of `RELIC_ENCRYPTION_KEY` outside Cloudflare. Without it, Relic
cannot read the secrets it stores, such as remote repository passwords.

## Deploy

Build the image, push it to Cloudflare's registry and deploy the Worker:

```bash
pnpm exec wrangler deploy
```

The first deploy takes several minutes while Cloudflare provisions the
container. Then open `https://relic.example.com/` and sign in as `admin`.

Follow the Worker's requests and errors:

```bash
pnpm exec wrangler tail
```

The container's own output (Relic's log) is in the Cloudflare dashboard, on the
container's page.

## Upgrade

Change the release tag in `deploy/cloudflare/Dockerfile`, then deploy again:

```bash
pnpm exec wrangler deploy
```

Cloudflare replaces the running container with one from the new image. Relic
applies database migrations when it starts.

## Run it locally

`wrangler dev` runs the Worker and the container on your machine, with Docker.
The disk lasts as long as the local container, so SQLite and a local directory
are enough for a test. Put these settings in `deploy/cloudflare/.dev.vars`:

```ini
RELIC_DATABASE_URL=sqlite:///var/lib/relic/data/relic.db
RELIC_OBJECT_STORAGE_TYPE=filesystem
RELIC_OBJECT_STORAGE_PATH=/var/lib/relic/data/objects
RELIC_ADMIN_PASSWORD=<admin-password>
RELIC_ENCRYPTION_KEY=<openssl rand -base64 32>
```

Start the Worker and the container on `http://localhost:8787`:

```bash
pnpm exec wrangler dev
```
