title: Quick start
description: Download the relic binary and run it as a systemd service with SQLite and a local directory; no other services needed.
---

The `relic` binary is the whole installation. `relic server start --worker`
serves the APIs and the web UI and runs the background jobs. SQLite holds the
metadata, and a local directory holds the content.

## Download

The install script downloads the latest release for Linux or macOS (amd64,
arm64). It checks the SHA-256 sum and puts `relic` in `~/.local/bin`:

```bash
curl -fsSL https://relic.build/install.sh | sh
```

Set `RELIC_VERSION` to pin a release and `RELIC_INSTALL_DIR` to change the
directory:

```bash
curl -fsSL https://relic.build/install.sh | sudo env RELIC_VERSION=vX.Y.Z RELIC_INSTALL_DIR=/usr/local/bin sh
```

A Relic server also serves the script at `/install.sh`.

Every release on GitHub (github.com/relicbuild/relic/releases) has these files:

- archives for Linux and macOS (amd64, arm64) and Windows (amd64), with the web
  UI built in
- `relic_<tag>_checksums.txt`, with the SHA-256 sums of the archives
- a cosign signature of that file (`relic_<tag>_checksums.txt.sigstore.json`)
- an SBOM per archive

To install by hand, pick the release:

```bash
v=vX.Y.Z
```

Download the archive and the checksum files:

```bash
gh release download "$v" --repo relicbuild/relic -p "relic_${v}_linux_amd64.tar.gz" -p "relic_${v}_checksums.txt*"
```

Check the signature of the sums (optional):

```bash
cosign verify-blob "relic_${v}_checksums.txt" --bundle "relic_${v}_checksums.txt.sigstore.json" --certificate-oidc-issuer https://token.actions.githubusercontent.com --certificate-identity-regexp '^https://github.com/relicbuild/relic/'
```

Check the archive against the sums:

```bash
sha256sum -c --ignore-missing "relic_${v}_checksums.txt"
```

Unpack the archive:

```bash
tar -xzf "relic_${v}_linux_amd64.tar.gz"
```

Install `relic` in `~/.local/bin`:

```bash
install "relic_${v}_linux_amd64/relic" ~/.local/bin/
```

Check the installed version:

```bash
relic --version
```

## Run as a service

Set up Relic as a service:

```bash
relic server setup
```

`relic server setup` lists every file and command it will touch and asks you
to confirm. Then it:

- writes `~/.config/relic/server.env` with a generated `RELIC_ENCRYPTION_KEY`
  and admin password
- keeps the database and files in `~/.local/share/relic`
- keeps the certificate authority and the server certificate in
  `~/.config/relic/tls` (`RELIC_TLS_DIRECTORY`)
- installs and starts a systemd user service that survives logouts and reboots
- adds shell completion to `~/.bashrc` (or zsh, fish)

Running it again changes nothing. The server listens on `127.0.0.1:8090` and
serves HTTPS with a certificate authority it generates
([TLS](/docs/installation/configuration#tls)). `--listen 0.0.0.0:8090` opens it
to the network. Clients on other machines then need
`~/.config/relic/tls/ca.crt`, and the certificate needs the name they use, in
`RELIC_TLS_HOSTNAMES`.

Read the generated admin password:

```bash
grep RELIC_ADMIN_PASSWORD ~/.config/relic/server.env
```

Sign in with the relic CLI. It shows the fingerprint of the server's
certificate authority and asks whether to trust it. Compare it with the
fingerprint in the server's log, or add `--ca-file ~/.config/relic/tls/ca.crt`:

```bash
relic auth login https://127.0.0.1:8090 --user admin
```

Check the service:

```bash
systemctl --user status relic
```

Follow the server's logs:

```bash
journalctl --user -u relic -f
```

To run a server that belongs to the machine instead of your user, use
`sudo relic server setup --system`. It creates a `relic` system user and copies
the binary to `/usr/local/bin`. It keeps the settings in `/etc/relic/relic.env`,
the certificate authority in `/etc/relic/tls` and the data in `/var/lib/relic`.
[Machine setup](/docs/cli/setup) describes both modes.

## Run by hand

Run Relic by hand when you have no systemd (macOS, Windows) or just want to
try it. Set the database, the content directory, the admin password and the
encryption key.

Create the data directory:

```bash
mkdir -p ~/relic-data
```

Keep a copy of the encryption key (see
[Backups](/docs/installation/single-binary/operations#backups)): Relic cannot
read its sealed secrets with another key. Generate the key once:

```bash
openssl rand -base64 32
```

These exports point Relic at the directory and set the admin password and the
key you generated:

```bash
export RELIC_DATABASE_URL="sqlite://$HOME/relic-data/relic.db"
export RELIC_OBJECT_STORAGE_TYPE=filesystem
export RELIC_OBJECT_STORAGE_PATH="$HOME/relic-data/objects"
export RELIC_ADMIN_PASSWORD='<password>'
export RELIC_ENCRYPTION_KEY='<key>'
```

The commands above are for a Unix shell. In PowerShell on Windows, set each
variable with `$env:NAME = 'value'`. The database URL is then `sqlite://`
followed by the absolute path, such as `sqlite://C:/relic-data/relic.db`.

Start the server and the worker in one process:

```bash
relic server start --worker
```

The server serves HTTPS on port 8090. It keeps a certificate authority it
generates in `~/.config/relic/tls` and logs the path of its `ca.crt`
([TLS](/docs/installation/configuration#tls)).

These settings make a single-node installation:

| Part | Setting |
| --- | --- |
| Metadata | `RELIC_DATABASE_URL=sqlite:///<dir>/relic.db` |
| Content | `RELIC_OBJECT_STORAGE_TYPE=filesystem`, `RELIC_OBJECT_STORAGE_PATH=<dir>/objects` |
| Process | `relic server start --worker` |

You can also choose the database and the content store separately: SQLite
with S3, or PostgreSQL with the filesystem store. Using either SQLite or the
filesystem store makes the installation a single node. The
[configuration reference](/docs/installation/configuration) lists every other
setting.

## Scanners

Relic Scan runs `syft`, `grype`, `gitleaks` and `trivy` from the `PATH`. The
archive does not include them. Install the ones you want (each project
publishes binaries), or run the [Docker image](/docs/installation/docker/quick-start),
which includes all four. Without them, the server runs with scanning off.

### Local scans with the JFrog® CLI

`jf scan` and `jf audit` download `relic-indexer` from the server and scan on
the client. The archive does not include `relic-indexer` builds (the Docker
image does), so on a single-binary installation these commands fail with
`404 Not Found` until you add them. Build one for each platform your clients
run, from the source of the release you installed.

Get the source of the release:

```bash
git clone --depth 1 --branch "$v" https://github.com/relicbuild/relic.git relic-src
```

Build `relic-indexer` for Linux on amd64 into `/var/lib/relic/indexer` (repeat
with the `GOOS` and `GOARCH` of each other platform; the name must stay
`relic-indexer-<os>-<arch>`, with `.exe` for Windows):

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go -C relic-src/api/adapters/artifactory/relic-indexer build -trimpath -o /var/lib/relic/indexer/relic-indexer-linux-amd64 .
```

Then point the server at the directory:

```ini
RELIC_INDEXER_DIR=/var/lib/relic/indexer
```
