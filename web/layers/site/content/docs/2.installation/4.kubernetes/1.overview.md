Every release publishes the Helm chart to `oci://ghcr.io/relicbuild/charts/relic`
(its source is `helm/relic`). It runs the server as a Deployment with two
replicas by default, and the worker as a second Deployment. By default it also
installs the components below. Each comes from its project's official chart, and
`Chart.lock` pins the versions.

| Component | Chart (values key) | Details |
| --- | --- | --- |
| CloudNativePG operator | `cloudnative-pg` (`postgresql-operator`) | Its CRDs are in the chart's `crds/` directory. |
| PostgreSQL, as a [CloudNativePG](https://cloudnative-pg.io) `Cluster` | `cnpg/cluster` (`postgresql`) | Three instances of 10Gi each, with a database named `relic`. CloudNativePG handles failover and generates the credentials Relic connects with. |
| SeaweedFS, with its S3 gateway | `seaweedfs` (`seaweedfs`) | The chart generates the S3 key pair and creates the `artifacts` and `temporary` buckets. |

Set `monitoringStack.enabled` to add a monitoring stack with Prometheus, Grafana,
Tempo, Loki and Alloy. See [Monitoring](/docs/installation/kubernetes/monitoring).

Values under `postgresql-operator`, `postgresql` and `seaweedfs` pass through to
the `cloudnative-pg`, `cluster` and `seaweedfs` charts, so you can use each
chart's own documentation for them.

## The CloudNativePG operator

One `helm install` brings up the operator and then the PostgreSQL cluster:

1. Helm installs the operator's CRDs from `crds/` first.
2. While the operator starts, its webhooks let the `Cluster` through.
3. Once running, the operator applies the `Cluster` defaults itself.

The `Cluster` is an ordinary part of the release. Upgrades change it in place and
never recreate it.

An operator owns cluster-wide resources such as CRDs and webhooks, so a Kubernetes
cluster can run only one. If your cluster already runs one, turn the bundled
operator off:

```yaml
postgresql-operator:
  enabled: false
```

If you turn it off and no operator runs in the cluster, the chart stops early and
prints the command to install one. If you use your own PostgreSQL, turn off both
`postgresql.enabled` and `postgresql-operator.enabled`.
