title: Upgrades and removal
description: Upgrade Relic with helm upgrade, and uninstall it with or without its data.
---

## Upgrade

Upgrade to a release with `helm upgrade` and the same values. Use
`--reset-then-reuse-values` instead of `--reuse-values`: `--reuse-values` also
keeps the old chart's defaults, so new settings and new dependencies do not get
their defaults.

```bash
helm upgrade relic oci://ghcr.io/relicbuild/charts/relic --version X.Y.Z -n relic --reset-then-reuse-values
```

- Migrations are forward-only. The server applies them before it reports ready,
  and the old pods keep serving until then. The startup probe allows five minutes.
- Downgrades are not supported. To go back, restore from a backup.
- On shutdown, the server waits for in-flight requests to finish, with a grace
  period of 120 seconds. Rolling restarts therefore do not cut uploads off.

Each release's chart pins its dependencies' versions; the release notes say
when one changes.

Helm installs CRDs only on the first install and never upgrades them. Before you
upgrade to a release with a new CloudNativePG operator, apply its CRDs. Download
the chart:

```bash
helm pull oci://ghcr.io/relicbuild/charts/relic --version X.Y.Z --untar
```

Apply the chart's copy of the CRDs:

```bash
kubectl apply --server-side -f relic/crds/cloudnative-pg.yaml
```

The same applies to the Prometheus Operator's CRDs when you turn on
`monitoringStack.enabled` for an existing release. See
[Monitoring](/docs/installation/kubernetes/monitoring#turning-it-on-for-an-existing-release).

## Uninstall

If you need the data, take a [backup](/docs/guides/operations#backup) before you
delete anything below, and keep a copy of the encryption key.

Remove the release:

```bash
helm uninstall relic -n relic
```

Three things remain after the release is gone:

- Volumes that StatefulSets created, and the single-node data volume.
- The chart's credentials Secret, `relic-credentials`, which holds the
  encryption key the data needs.
- The SeaweedFS S3 Secret, which the SeaweedFS chart keeps.

A new install into the same namespace reads them back. To start again from
nothing, delete them. List the volume claims:

```bash
kubectl -n relic get pvc
```

Delete all volume claims in the namespace:

```bash
kubectl -n relic delete pvc --all
```

Delete the credentials Secret:

```bash
kubectl -n relic delete secret relic-credentials
```

Delete the SeaweedFS S3 Secret:

```bash
kubectl -n relic delete secret relic-seaweedfs-s3-secret
```
