## Values

| Value | Default | Sets |
| --- | --- | --- |
| `image.repository`, `image.tag` | `ghcr.io/relicbuild/relic`, `v` and the chart's `appVersion` | The Relic image; the default tag is the release's. |
| `image.pullPolicy`, `imagePullSecrets` | `IfNotPresent`, `[]` | The image pull policy, and the Secrets for a private registry. |
| `existingCredentialsSecret` | (none) | A Secret of your own with the [keys below](#secret-keys). When empty, the chart creates `<release>-relic-credentials` from `credentials.*`. |
| `credentials.*` | (none) | The keys of the Secret the chart creates, one value per [key below](#secret-keys), such as `credentials.databaseURL`. `credentials.encryptionKey` is required. Without `credentials.adminPassword`, the chart derives a password from the encryption key. |
| `database.engine` | `postgresql` | `postgresql` or `sqlite`. With `sqlite`, the database is a file on the data volume and Relic runs as a single node ([Single node](/docs/installation/kubernetes/quick-start#single-node)). `sqlite` needs `postgresql.enabled` and `postgresql-operator.enabled` off. |
| `objectStorage.type` | `s3` | `s3`, `azure` (Azure Blob Storage), `gcs` (Google Cloud Storage) or `filesystem`. With `filesystem`, the content is on the data volume and Relic runs as a single node. Every type but `s3` needs `seaweedfs.enabled` off. |
| `data.size`, `data.storageClass` | `20Gi`, the cluster's default | The data volume of a single node, mounted at `/var/lib/relic/data`. It is kept when you uninstall. When `database.engine` is `sqlite` or `objectStorage.type` is `filesystem`, the chart runs one server pod with `relic server start --worker`. It then creates no worker Deployment, autoscaler or disruption budget, and refuses any `server.replicas` other than 1. |
| `objectStorage.endpoint` | SeaweedFS's S3 gateway | `RELIC_OBJECT_STORAGE_ENDPOINT`. With `seaweedfs.enabled` off, the chart requires it except for `gcs`, for `s3` with `objectStorage.defaultCredentials` (empty means Amazon S3), and for `azure` with a connection string. For Amazon S3 with a static key pair, set the regional endpoint, such as `https://s3.eu-central-1.amazonaws.com`. |
| `objectStorage.region` | `us-east-1` | `RELIC_OBJECT_STORAGE_REGION`. |
| `objectStorage.checksum` | `when_supported` | `RELIC_OBJECT_STORAGE_CHECKSUM`. |
| `objectStorage.artifactsBucket`, `objectStorage.temporaryBucket` | `artifacts`, `temporary` | `RELIC_OBJECT_STORAGE_ARTIFACTS_BUCKET`, `RELIC_OBJECT_STORAGE_TEMPORARY_BUCKET`. |
| `objectStorage.defaultCredentials` | `false` | `true` reads no key from the credentials Secret: the platform's identity authenticates (IRSA or EKS Pod Identity for `s3`, workload or managed identity for `azure`, workload identity for `gcs`). Annotate the service account through `serviceAccount.annotations`. |
| `objectStorage.serverSideEncryption` | (none) | `RELIC_OBJECT_STORAGE_SSE`: `AES256` or `aws:kms`, for every S3 write. |
| `objectStorage.sseKmsKeyId` | (none) | `RELIC_OBJECT_STORAGE_SSE_KMS_KEY_ID`: the KMS key for `aws:kms`. |
| `objectStorage.storageClass` | (none) | `RELIC_OBJECT_STORAGE_STORAGE_CLASS`: the storage class of every S3 write. |
| `postgresql-operator.enabled`, `postgresql-operator.*` | on | The bundled CloudNativePG operator. `postgresql-operator.*` are its chart's values. Turn it off if the cluster already runs an operator. |
| `postgresql.enabled`, `postgresql.*` | on | The `cnpg/cluster` chart's values (instances, storage, backups, monitoring). |
| `seaweedfs.enabled`, `seaweedfs.*` | on | The `seaweedfs` chart's values. Keep `seaweedfs.s3.createBuckets` in step with the bucket names. |
| `server.replicas`, `server.autoscaling.*` | `2`, off | Server pods. A PodDisruptionBudget (`server.podDisruptionBudget.*`) keeps one pod running while a node drains. The chart leaves it out when the fewest server pods (`server.replicas`, or `server.autoscaling.minReplicas` with autoscaling) are not more than its `minAvailable` (a percentage of them, rounded up), since it would then block the drain. |
| `server.temporaryVolumeSize` | `10Gi` | The `emptyDir` at `/tmp`. Relic uses it to export and import release bundles and to browse archives. |
| `worker.replicas`, `worker.temporaryVolumeSize` | `1`, `20Gi` | The worker. More than one replica needs `worker.vulnerabilityDatabase.persistence` off, because that volume is ReadWriteOnce. A single node runs the worker in the server pod, whose `/tmp` is `server.temporaryVolumeSize`. |
| `worker.vulnerabilityDatabase.*` | persisted, `5Gi` | Relic Scan's vulnerability database. Without persistence, the worker downloads it again after every restart, into an emptyDir that `size` limits. |
| `tls.enabled` | on | The server serves HTTPS ([The server's certificate](/docs/installation/kubernetes/exposing#the-servers-certificate)). Off adds `--no-tls`, and the server serves plain HTTP. The probes follow it. |
| `tls.existingSecret` | (none) | A `kubernetes.io/tls` Secret, for example from cert-manager, mounted at `/etc/relic/tls`. It sets `RELIC_TLS_CERTIFICATE_FILE=/etc/relic/tls/tls.crt` and `RELIC_TLS_KEY_FILE=/etc/relic/tls/tls.key`. Without it, each pod generates its own certificate authority, on the data volume of a single node and in an `emptyDir` otherwise, where it changes on restart. Clients that verify the server need it. |
| `tls.hostnames` | `[]` | Extra names for the generated certificate (`RELIC_TLS_HOSTNAMES`). The chart already adds the Service's names and the ingress hosts. |
| `tls.minVersion` | `"1.2"` | The oldest TLS version clients may use, `"1.2"` or `"1.3"` (`RELIC_TLS_MIN_VERSION`). |
| `ingress.*` | disabled | Host names, class, annotations and TLS. Raise the controller's body size limit for large uploads. While `tls.enabled` is on, the chart adds `nginx.ingress.kubernetes.io/backend-protocol: HTTPS` unless you set it. |
| `service.type`, `service.port`, `service.nodePort` | `ClusterIP`, `443` (`80` with `tls.enabled` off) | How the server is exposed inside the cluster. |
| `trustedProxies` | the private ranges | `RELIC_TRUSTED_PROXIES`. Narrow it to the ingress controller's pod CIDR. |
| `ldap.caCertificate` | (none) | A PEM CA certificate to trust for LDAP servers. See [LDAP](/docs/guides/security/ldap). |
| `networkPolicy.enabled`, `networkPolicy.allowServerAccessFrom` | on, (anyone) | Who may reach the server. `networkPolicy.allowServerAccessFrom` lists NetworkPolicy peers. Once set, only they get through, so include the ingress controller's namespace ([Exposing Relic](/docs/installation/kubernetes/exposing#network-policy)). |
| `serviceAccount.create`, `serviceAccount.name`, `serviceAccount.annotations` | on, `<release>-relic`, (none) | The service account of the server and worker pods, which do not mount its token. With `serviceAccount.create` off, the pods use `serviceAccount.name`, or `default`. The annotations bind a cloud identity for `objectStorage.defaultCredentials`, such as `eks.amazonaws.com/role-arn`. |
| `podLabels` | (none) | Labels for the server and worker pods, such as `azure.workload.identity/use: "true"`. |
| `podSecurityContext`, `securityContext` | user and group 65532, non-root, `RuntimeDefault` seccomp; no privilege escalation, a read-only root filesystem, no capabilities | The pods' and the containers' security contexts. See [Hardening](/docs/installation/kubernetes/hardening). |
| `metrics.enabled` | on | Serves `/metrics` on port 8091 of every pod. Adds a headless `<release>-relic-metrics` Service and a NetworkPolicy rule that allows scrapes. `metrics.allowScrapesFrom` narrows that rule. |
| `metrics.serviceMonitor.*`, `metrics.prometheusRule.*` | on | A ServiceMonitor and Relic's alert rules. The chart adds them only when the Prometheus Operator's API exists. `metrics.prometheusRule.runbookBaseURL` is the prefix of the runbook links. |
| `metrics.repositoryNameLabel`, `metrics.profiling` | off | `RELIC_METRICS_REPOSITORY_LABEL`, `RELIC_PROFILING_ENABLED`. |
| `tracing.otlpEndpoint`, `tracing.sampler`, `tracing.samplerArg` | (none), `parentbased_traceidratio`, `0.1` | `OTEL_EXPORTER_OTLP_ENDPOINT` and the sampler. With `monitoringStack.enabled`, the endpoint defaults to the bundled Alloy. |
| `logging.level`, `logging.format`, `logging.otlp` | `info`, `json`, off | `RELIC_LOG_LEVEL`, `RELIC_LOG_FORMAT`, `OTEL_LOGS_EXPORTER=otlp`. |
| `grafana.dashboards.*` | off | Relic's dashboards as ConfigMaps for a Grafana dashboard sidecar. You can set the label and folder. Always on with `monitoringStack.enabled`. |
| `monitoringStack.enabled` | off | The monitoring stack. See [Monitoring](/docs/installation/kubernetes/monitoring). `kube-prometheus-stack.*`, `tempo.*`, `loki.*` and `alloy.*` are those charts' values. |
| `extraEnv` | `[]` | Any other variable from the [configuration reference](/docs/installation/configuration). The chart sets them on the server and the worker. |
| `*.nodeSelector`, `*.tolerations`, `*.affinity`, `*.resources` | | Scheduling and resources per component. The server's memory limit sets how many uploads run at once ([Memory and concurrent uploads](/docs/guides/operations#memory-and-concurrent-uploads)). |

For example, these values let remote repositories proxy an internal registry:

```yaml
extraEnv:
  - name: RELIC_UPSTREAM_ALLOW_PRIVATE_ADDRESSES
    value: "true"
```

## Secret keys

These are the keys of the Secret the chart creates, or of the Secret that `existingCredentialsSecret` names:

| Key | Variable | Notes |
| --- | --- | --- |
| `databaseURL` | `RELIC_DATABASE_URL` | Used only when `postgresql.enabled` is off and `database.engine` is `postgresql`. Otherwise Relic reads the URL from CloudNativePG's `<release>-postgresql-app` Secret, or needs none (SQLite). |
| `objectStorageAccessKey`, `objectStorageSecretKey` | `RELIC_OBJECT_STORAGE_ACCESS_KEY`, `RELIC_OBJECT_STORAGE_SECRET_KEY` | Used only when `seaweedfs.enabled` is off, `objectStorage.type` is `s3` and `objectStorage.defaultCredentials` is off. Otherwise Relic reads the keys from SeaweedFS's S3 Secret, or needs none. |
| `objectStorageAzureConnectionString` | `RELIC_OBJECT_STORAGE_AZURE_CONNECTION_STRING` | Used only when `objectStorage.type` is `azure` and `objectStorage.defaultCredentials` is off. |
| `adminPassword` | `RELIC_ADMIN_PASSWORD` | Relic uses it to create `admin` on the first start only, and does not start on an empty database without it. The chart derives one in the Secret it creates; a Secret of your own needs it for the first install. |
| `encryptionKey` | `RELIC_ENCRYPTION_KEY` | Required (`openssl rand -base64 32`). The chart does not generate one: a generated key would change on every `helm template` or Argo CD sync. The chart's Secret is kept when you uninstall, like the data volume; keep your own copy of the key apart from the backups. |
