---
title: Quick start
description: Install Relic with the chart's defaults, with PostgreSQL (CloudNativePG) and SeaweedFS running in the cluster.
---

These steps assume the cluster does not run a CloudNativePG operator yet, because
the chart installs one. If your cluster already runs one, see
[the overview](/docs/installation/kubernetes/overview#the-cloudnativepg-operator).

The chart's dependencies come from four Helm repositories. Add the CloudNativePG
repository:

```bash
helm repo add cnpg https://cloudnative-pg.github.io/charts
```

Add the SeaweedFS repository:

```bash
helm repo add seaweedfs https://seaweedfs.github.io/seaweedfs/helm
```

Add the Prometheus community repository:

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
```

Add the Grafana repository:

```bash
helm repo add grafana https://grafana.github.io/helm-charts
```

Download the dependencies into the chart:

```bash
helm dependency build helm/relic
```

Create the encryption key, which seals the passwords and signing keys Relic
stores. Keep a copy apart from your backups: without it, those secrets cannot be
read back.

```bash
export RELIC_ENCRYPTION_KEY="$(openssl rand -base64 32)"
```

Create the password that Relic gives the `admin` user on the first start:

```bash
export RELIC_ADMIN_PASSWORD="$(openssl rand -base64 18)"
```

Install Relic into the `relic` namespace:

```bash
helm install relic helm/relic -n relic --create-namespace --set credentials.encryptionKey="$RELIC_ENCRYPTION_KEY" --set credentials.adminPassword="$RELIC_ADMIN_PASSWORD"
```

Print the admin password from the chart's Secret:

```bash
kubectl -n relic get secret relic-credentials -o jsonpath='{.data.adminPassword}' | base64 -d
```

On the first install, the server pods restart a few times while PostgreSQL
starts. They become ready once the database accepts connections.

Check the state of the PostgreSQL cluster:

```bash
kubectl -n relic get cluster relic-postgresql
```

Check the pods:

```bash
kubectl -n relic get pods
```

If you have no ingress yet, forward a local port to the Relic Service:

```bash
kubectl -n relic port-forward svc/relic 8090:443
```

Open `https://localhost:8090` and sign in as `admin` with the password you printed
above. Then [sign in with the relic CLI](/docs/cli/sign-in).

The server serves HTTPS. With the defaults, each pod generates its own
certificate authority and a new one when it restarts. The browser warns about
the certificate, and the CLI asks whether to trust its authority. For a certificate that clients can verify, set
`tls.existingSecret` ([The server's certificate](/docs/installation/kubernetes/exposing#the-servers-certificate)).

## Names

If your release name is not `relic`, the chart names objects as follows:

- Relic's objects: `<release>-relic`
- The PostgreSQL cluster: `<release>-postgresql`
- SeaweedFS: `<release>-seaweedfs`

## What the chart sets up

- It refuses to render without `credentials.encryptionKey` and
  `credentials.adminPassword`, or `existingCredentialsSecret`. A key or
  password generated by the chart would change on every `helm template` or
  Argo CD sync: the stored secrets would be lost, and the Secret would no
  longer hold the password of `admin`. On `helm upgrade` it reads both back
  from its Secret when the values leave them out.
- It keeps its Secret, with the encryption key, when you uninstall, as it keeps
  the data volume.
- It points Relic at the database URI in CloudNativePG's
  `<release>-postgresql-app` Secret, and at the S3 key pair in SeaweedFS's
  `<release>-seaweedfs-s3-secret`.
- It gives the `temporary` bucket no TTL. The worker deletes `temporary` objects
  older than a day, but not incomplete multipart uploads, which listings do not
  show. Add a TTL to remove those (see [SeaweedFS](/docs/installation/storage/seaweedfs#the-helm-charts-bundled-seaweedfs)).

## Small or test cluster

These values run fewer, smaller PostgreSQL instances and one server replica:

```yaml
server:
  replicas: 1
postgresql:
  cluster:
    instances: 1
    storage:
      size: 2Gi
```

Save them as `small.yaml` and install with them:

```bash
helm install relic helm/relic -n relic --create-namespace -f small.yaml --set credentials.encryptionKey="$RELIC_ENCRYPTION_KEY" --set credentials.adminPassword="$RELIC_ADMIN_PASSWORD"
```

## Single node

These values run one pod on SQLite and a volume, without PostgreSQL or SeaweedFS:

```yaml
database:
  engine: sqlite
objectStorage:
  type: filesystem
postgresql:
  enabled: false
postgresql-operator:
  enabled: false
seaweedfs:
  enabled: false
server:
  replicas: 1
data:
  size: 50Gi
```

The chart then runs one pod with `relic server start --worker` on a ReadWriteOnce
volume named `<release>-relic-data`. The volume also holds the generated
certificate authority, so it survives restarts. The volume is kept when you
uninstall the release. Kubernetes replaces the pod with the Recreate strategy. The chart refuses
more than one replica and refuses autoscaling.
[Limits and backups](/docs/installation/single-binary/operations) apply.
