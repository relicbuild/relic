---
title: PostgreSQL and S3
description: Run a Relic server and worker container against your own PostgreSQL and S3-compatible storage.
---

You need the [image](/docs/installation/docker/quick-start#get-the-image), a
PostgreSQL database and two buckets on an S3-compatible store (see
[Storage](/docs/installation/storage/overview)).

Put the settings in an env file outside the repository, for example `relic.env`.
It holds these lines:

```ini
RELIC_DATABASE_URL=postgres://relic:<password>@db.example.com:5432/relic?sslmode=require
RELIC_OBJECT_STORAGE_ENDPOINT=https://s3.eu-central-1.amazonaws.com
RELIC_OBJECT_STORAGE_REGION=eu-central-1
RELIC_OBJECT_STORAGE_ARTIFACTS_BUCKET=example-relic-artifacts
RELIC_OBJECT_STORAGE_TEMPORARY_BUCKET=example-relic-temporary
RELIC_OBJECT_STORAGE_ACCESS_KEY=<access-key>
RELIC_OBJECT_STORAGE_SECRET_KEY=<secret-key>
RELIC_ADMIN_PASSWORD=<admin-password>
RELIC_ENCRYPTION_KEY=<openssl rand -base64 32>
```

Start one server:

```bash
docker run -d --name relic --env-file relic.env -p 8090:8090 ghcr.io/relicbuild/relic:latest server start
```

Start one worker:

```bash
docker run -d --name relic-worker --env-file relic.env \
  -v relic-grype:/var/lib/relic/grype ghcr.io/relicbuild/relic:latest server worker
```

The worker keeps Grype's vulnerability database in `/var/lib/relic/grype`. Without
a volume there, it downloads the database again after every restart.

Add more servers behind a load balancer as you need them.

The server serves HTTPS. Each container generates its own certificate
authority, so servers behind a load balancer need one certificate that clients
trust. Mount it into every server container and set `RELIC_TLS_CERTIFICATE_FILE`
and `RELIC_TLS_KEY_FILE` ([TLS](/docs/installation/configuration#tls)). Or run
`server start --no-tls` behind a reverse proxy that terminates TLS, and list the
proxy in `RELIC_TRUSTED_PROXIES` (see [Behind a reverse proxy](/docs/guides/operations#behind-a-reverse-proxy)).
