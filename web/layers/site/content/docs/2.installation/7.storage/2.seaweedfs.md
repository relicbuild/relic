Relic is built and tested against SeaweedFS. The Compose stack, the Helm chart's
bundled store and the end-to-end tests all use it (image
`chrislusf/seaweedfs:4.48`). It is the recommended choice for self-hosting.

## Why SeaweedFS

- Uploads, range reads, the readiness check, garbage collection, and the backup
  and restore drill are all tested against its S3 gateway.
- It supports TTLs per path. `fs.configure` gives the `temporary` bucket a
  one-day TTL, so abandoned uploads expire without a lifecycle job.
- Replication is configurable. A placement such as `010` keeps a copy on another
  rack. Relic's content never changes and is stored once, which suits
  SeaweedFS's volume design.
- It is Apache 2.0 licensed and ships as one binary. The master, volume, filer
  and S3 gateway need no external dependencies.

## Architecture

| Component | Role |
| --- | --- |
| master | Assigns volumes and enforces replication. Run three for high availability. |
| volume servers | Store the data. |
| filer | Maps bucket paths to data. Give it its own metadata store (leveldb2 for small setups, or a database). Never use Relic's PostgreSQL. |
| S3 gateway | The endpoint Relic talks to, on port 8333. |

## Setup

**1. S3 identity.** SeaweedFS reads S3 identities from a JSON file. Pass the file
to the gateway with `-config`, or with `-s3.config` for `weed server`:

```json
{
  "identities": [
    {
      "name": "relic",
      "credentials": [{ "accessKey": "<access-key>", "secretKey": "<secret-key>" }],
      "actions": ["Read", "Write", "List", "Tagging"]
    }
  ]
}
```

Relic creates and deletes no buckets, so its identity needs no `Admin`: the
buckets are created in step 2 with `weed shell`. Once identities are
configured, the gateway refuses anonymous requests.

**2. Buckets and the `temporary` TTL.** This `weed shell` session creates both
buckets and gives `temporary` a one-day TTL:

```bash
weed shell -master=<master>:9333 -filer=<filer>:8888 <<'EOF'
s3.bucket.create -name artifacts
s3.bucket.create -name temporary
fs.configure -locationPrefix=/buckets/temporary/ -ttl=1d -apply
EOF
```

Each bucket becomes its own SeaweedFS collection. To set the replication of
`artifacts`, run an `fs.configure` for `/buckets/artifacts/` with
`-replication=010` (or another placement). You can also start the master with
`-defaultReplication`.

**3. Connection:**

```ini
RELIC_OBJECT_STORAGE_ENDPOINT=http://seaweedfs-s3.storage:8333
RELIC_OBJECT_STORAGE_ACCESS_KEY=<access-key>
RELIC_OBJECT_STORAGE_SECRET_KEY=<secret-key>
```

You can leave `RELIC_OBJECT_STORAGE_REGION` at `us-east-1`. Bucket names default
to `artifacts` and `temporary`.

Helm:

```yaml
seaweedfs:
  enabled: false
existingCredentialsSecret: relic          # holds objectStorageAccessKey and objectStorageSecretKey
objectStorage:
  endpoint: http://seaweedfs-s3.storage:8333
```

## The Helm chart's bundled SeaweedFS

`seaweedfs.enabled=true` installs SeaweedFS from its official chart
(`seaweedfs` 4.48.0, pinned in `Chart.yaml`). Each component runs in its own
pod, with one replica:

| Component | Kubernetes object |
| --- | --- |
| master | StatefulSet `<release>-seaweedfs-master` |
| volume server | StatefulSet `<release>-seaweedfs-volume` |
| filer | StatefulSet `<release>-seaweedfs-filer`, with a leveldb2 metadata store |
| S3 gateway | Deployment `<release>-seaweedfs-s3`, on port 8333 |

Relic's `values.yaml` sets the storage and the S3 gateway's values:

- The master, the volume server and the filer keep their data on
  PersistentVolumeClaims of the default StorageClass, which follow a
  rescheduled pod: 1 GiB (`seaweedfs.master.data.size`), 50 GiB
  (`seaweedfs.volume.dataDirs[0].size`) and 10 GiB
  (`seaweedfs.filer.data.size`). Set `storageClass` next to each size to use
  another class. Logs go to `emptyDir`.

- `seaweedfs.s3.enableAuth` turns on S3 authentication. The SeaweedFS chart
  generates the key pair in the `<release>-seaweedfs-s3-secret` Secret, and
  Relic reads `admin_access_key_id` and `admin_secret_access_key` from it.
- `seaweedfs.s3.createBuckets` lists the buckets. After every install and
  upgrade, a Job of the SeaweedFS chart creates the ones that do not exist yet.
  Keep the list in step with `objectStorage.artifactsBucket` and
  `objectStorage.temporaryBucket`.

Everything else is the SeaweedFS chart's default: one replica of each, and
nothing is replicated (`000`).

`temporary` has no TTL. The worker deletes `temporary` objects older than a
day, but not incomplete multipart uploads, which listings do not show. A `ttl`
on the bucket removes them. These values give `temporary` a one-day TTL:

```yaml
seaweedfs:
  s3:
    createBuckets:
      - name: artifacts
      - name: temporary
        ttl: 1d
```

The bundled store keeps one copy of each object. For production, run a
replicated SeaweedFS, for example with more volume servers and a replication
setting through the SeaweedFS chart's values, or with the SeaweedFS operator.
For a SeaweedFS outside the release, point `objectStorage.endpoint` at its S3
gateway.

## Gotchas

- **TLS.** The S3 gateway speaks plain HTTP unless you configure TLS. Keep it on
  a private network, or give it a certificate from a public CA. There is no
  setting for a private CA (see [the overview](/docs/installation/storage/overview#what-relic-does-not-support)).
- **Volume size.** `-volumeSizeLimitMB` caps the size of each volume. The bundled
  store keeps the SeaweedFS chart's default, 1000
  (`seaweedfs.master.volumeSizeLimitMB`). The volume servers need room for as
  many volumes as the data fills. `-max=0` sets the volume count from free disk
  space. In the chart, that is `maxVolumes: 0` in `seaweedfs.volume.dataDirs`,
  the default.
- **Filer metadata is state.** Back it up with the volumes, or keep a copy of the
  `artifacts` bucket elsewhere with an S3 sync tool. See [Backup](/docs/guides/operations#backup).
