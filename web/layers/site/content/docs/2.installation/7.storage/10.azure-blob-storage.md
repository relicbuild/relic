---
title: Azure Blob Storage
description: Azure Blob Storage as object storage, with workload identity, a managed identity or a connection string.
---

Relic stores content in two containers of a storage account
(`RELIC_OBJECT_STORAGE_TYPE=azure`). It authenticates with the default Azure
credential (AKS workload identity, a managed identity, or the `AZURE_*`
environment variables), or with a connection string that holds the account
key.

## Create the containers

This command creates the artifacts container:

```bash
az storage container create --account-name examplerelic --name artifacts --auth-mode login
```

This command creates the temporary container:

```bash
az storage container create --account-name examplerelic --name temporary --auth-mode login
```

Leave blob versioning and soft delete off for the artifacts container: objects
that garbage collection deletes would still cost storage. A lifecycle
management rule that deletes blobs in `temporary` after one day cleans up
uploads a crash left behind.

## Permissions

Grant Relic's identity the `Storage Blob Data Contributor` role on the storage
account:

```bash
az role assignment create --assignee <client-id> --role "Storage Blob Data Contributor" \
  --scope /subscriptions/<subscription>/resourceGroups/<group>/providers/Microsoft.Storage/storageAccounts/examplerelic
```

## Settings

```ini
RELIC_OBJECT_STORAGE_TYPE=azure
RELIC_OBJECT_STORAGE_ENDPOINT=https://examplerelic.blob.core.windows.net
RELIC_OBJECT_STORAGE_ARTIFACTS_BUCKET=artifacts
RELIC_OBJECT_STORAGE_TEMPORARY_BUCKET=temporary
```

With a connection string instead of an identity, set
`RELIC_OBJECT_STORAGE_AZURE_CONNECTION_STRING`; the endpoint then comes from
it.

Helm, with AKS workload identity:

```yaml
seaweedfs:
  enabled: false
serviceAccount:
  annotations:
    azure.workload.identity/client-id: <client-id>
podLabels:
  azure.workload.identity/use: "true"
objectStorage:
  type: azure
  defaultCredentials: true
  endpoint: https://examplerelic.blob.core.windows.net
  artifactsBucket: artifacts
  temporaryBucket: temporary
```

## Limitations

- **Copies stream through Relic.** Moving new content from `temporary` into
  `artifacts` reads and writes it again, because a server-side copy needs the
  source authorized separately under Entra ID.
