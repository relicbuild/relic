---
title: Cloudflare R2
description: Cloudflare R2 as object storage, through its S3-compatible API.
---

R2 has no egress fees. This matters because every download reads from the
bucket.

## Create the buckets

In the Cloudflare dashboard, open **R2 Object Storage** and create two buckets,
for example `relic-artifacts` and `relic-temporary`. Give both the same location
hint (or jurisdiction). Leave public access and custom domains off. Relic reaches
the buckets through the S3 API only.

You can also create the buckets with Wrangler. This command creates the
artifacts bucket:

```bash
npx wrangler r2 bucket create relic-artifacts
```

This command creates the temporary bucket:

```bash
npx wrangler r2 bucket create relic-temporary
```

## Lifecycle rules

| Bucket | Rules (**Settings → Object lifecycle rules**) |
| --- | --- |
| relic-temporary | One rule for the whole bucket: delete objects 1 day after upload, and abort incomplete multipart uploads after 1 day. |
| relic-artifacts | Only the rule that aborts incomplete multipart uploads. R2 adds a 7-day rule to new buckets. |

## API token

Under **R2 Object Storage → Manage API tokens**, create a token with **Object
Read & Write** permission, limited to the two buckets. Cloudflare shows an
**Access Key ID** and a **Secret Access Key** once. They are Relic's key pair.

## Settings

```ini
RELIC_OBJECT_STORAGE_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
RELIC_OBJECT_STORAGE_REGION=auto
RELIC_OBJECT_STORAGE_ARTIFACTS_BUCKET=relic-artifacts
RELIC_OBJECT_STORAGE_TEMPORARY_BUCKET=relic-temporary
RELIC_OBJECT_STORAGE_ACCESS_KEY=<access-key-id>
RELIC_OBJECT_STORAGE_SECRET_KEY=<secret-access-key>
```

`<account-id>` is the Cloudflare account ID from the R2 overview page. Buckets in
a jurisdiction use that jurisdiction's endpoint, for example
`https://<account-id>.eu.r2.cloudflarestorage.com`.

Helm:

```yaml
seaweedfs:
  enabled: false
existingCredentialsSecret: relic          # holds the S3 key pair, adminPassword and encryptionKey
objectStorage:
  endpoint: https://<account-id>.r2.cloudflarestorage.com
  region: auto
  artifactsBucket: relic-artifacts
  temporaryBucket: relic-temporary
```

## Gotchas

- **Region.** R2 signs with the region `auto`. It also accepts `us-east-1`, the
  default, but set `auto` to be explicit.
- **Path-style URLs.** Relic always sends path-style requests
  (`https://<account-id>.r2.cloudflarestorage.com/<bucket>/<key>`). R2 supports
  them.
- **One account, one token for both buckets.** Relic copies objects from the
  temporary bucket to the artifacts bucket server-side, with one key pair. A
  token scoped to one bucket makes every upload fail.
- **Checksums.** Uploads carry the AWS SDK's default CRC32 checksums. After
  setup, upload a file of a few hundred megabytes. If the upload fails with a
  checksum error in the server log, set `RELIC_OBJECT_STORAGE_CHECKSUM` to
  `when_required` (`objectStorage.checksum` in the Helm chart), which sends
  checksums only where S3 requires them.
- **Latency.** Run Relic in a region close to the buckets' location. Every
  download, and the copy step of every upload, is a round trip to R2.
