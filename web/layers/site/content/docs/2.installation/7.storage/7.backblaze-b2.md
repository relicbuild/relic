---
title: Backblaze B2
description: Backblaze B2 as object storage, through its S3-compatible API.
---

B2's S3-compatible API supports multipart uploads, server-side copies and range
reads. Relic is not tested against B2, so run an upload and a download test
before production.

## Create the buckets

In the B2 web console, create two **private** buckets, for example
`example-relic-artifacts` and `example-relic-temporary`. Bucket names are global
across B2. Note the bucket's **Endpoint**, such as
`s3.us-west-004.backblazeb2.com`. The part between `s3.` and `.backblazeb2.com`
is the region.

## Lifecycle settings

By default, B2 keeps every version of a file. A delete through the S3 API only
hides the file. Garbage collection therefore frees no space until B2 removes the
hidden versions. Set these under **Lifecycle Settings**:

| Bucket | Setting |
| --- | --- |
| artifacts | **Keep only the last version of the file**. |
| temporary | A custom rule for all files: hide files 1 day after upload, and delete them 1 day after they are hidden. |

## Application key

Under **Application Keys**, add a key with **Read and Write** access to both
buckets. Relic copies objects from the temporary bucket to the artifacts bucket
with one key pair, so a key restricted to one bucket makes every upload fail. B2
shows the **keyID** and **applicationKey** once. They are Relic's key pair.

## Settings

```ini
RELIC_OBJECT_STORAGE_ENDPOINT=https://s3.us-west-004.backblazeb2.com
RELIC_OBJECT_STORAGE_REGION=us-west-004
RELIC_OBJECT_STORAGE_ARTIFACTS_BUCKET=example-relic-artifacts
RELIC_OBJECT_STORAGE_TEMPORARY_BUCKET=example-relic-temporary
RELIC_OBJECT_STORAGE_ACCESS_KEY=<keyID>
RELIC_OBJECT_STORAGE_SECRET_KEY=<applicationKey>
```

The region must match the endpoint.

Helm:

```yaml
seaweedfs:
  enabled: false
existingCredentialsSecret: relic          # holds objectStorageAccessKey and objectStorageSecretKey
objectStorage:
  endpoint: https://s3.us-west-004.backblazeb2.com
  region: us-west-004
  artifactsBucket: example-relic-artifacts
  temporaryBucket: example-relic-temporary
```

## Gotchas

- **Path-style URLs.** Requests go to `https://s3.<region>.backblazeb2.com/<bucket>/<key>`.
  B2 supports this.
- **Checksums.** Uploads carry the AWS SDK's default CRC32 checksums. If B2
  rejects them, uploads fail and the server log shows the S3 error; set
  `RELIC_OBJECT_STORAGE_CHECKSUM` to `when_required` (`objectStorage.checksum`
  in the Helm chart) to send checksums only where S3 requires them.
- **Downloads cost transactions.** Each download and each `HEAD` is a B2 API
  call. With the Helm chart, the readiness probe adds one `HEAD` every 10 seconds
  per server pod. Once a day, the worker's storage check lists the artifacts
  bucket and reads up to 10 GiB of content back.
