---
title: Other S3-compatible services
description: Checklist and settings for Ceph RGW, Wasabi, DigitalOcean Spaces and other S3-compatible stores.
---

Any service that implements the S3 operations below works. Relic depends on
every item in the checklist and has no setting to work around a missing one.

## Checklist

- Path-style requests (`<endpoint>/<bucket>/<key>`). Relic sends no other style.
- Signature Version 4 with a static access key and secret key.
- Multipart uploads (`CreateMultipartUpload`, `UploadPart`,
  `CompleteMultipartUpload`, `AbortMultipartUpload`) with parts of 5 MiB or
  more, all but the last of one size.
- Server-side copy between two buckets with one key pair: `CopyObject`, and
  `UploadPartCopy` for objects over 5 GiB.
- Range reads on `GetObject`.
- `ListObjectsV2` on both buckets. Garbage collection lists the temporary
  bucket, and the daily storage check lists the artifacts bucket.
- `HeadObject` on a missing key answers 404, not 403. The readiness check
  depends on it.
- The service accepts the AWS SDK for Go v2's default upload checksums (CRC32),
  or `RELIC_OBJECT_STORAGE_CHECKSUM` is `when_required`.
- A way to expire objects in the temporary bucket after a day: a lifecycle rule,
  a TTL, or a scheduled job of your own.
- Deletes free space, or a lifecycle rule removes old versions.
- A certificate from a public CA on `https://` endpoints, or a private network
  over `http://`. There is no custom CA setting.

The [overview](/docs/installation/storage/overview) explains each requirement.

## Common settings

Use these values as a starting point, and confirm the endpoint and region in the
provider's console.

| Service | `RELIC_OBJECT_STORAGE_ENDPOINT` | `RELIC_OBJECT_STORAGE_REGION` |
| --- | --- | --- |
| Ceph Object Gateway (RGW) | `http://<rgw-host>:7480`, or your TLS front end | The zonegroup's API name |
| Wasabi | `https://s3.<region>.wasabisys.com` | The bucket's region, such as `eu-central-1` |
| DigitalOcean Spaces | `https://<region>.digitaloceanspaces.com` | The region, such as `fra1` |
| Garage | `http://<garage-host>:3900` | The `s3_region` from Garage's configuration |

Create two buckets and a key pair with read, write, list and delete access to
both.
Then set:

```ini
RELIC_OBJECT_STORAGE_ENDPOINT=<endpoint>
RELIC_OBJECT_STORAGE_REGION=<region>
RELIC_OBJECT_STORAGE_ARTIFACTS_BUCKET=<artifacts-bucket>
RELIC_OBJECT_STORAGE_TEMPORARY_BUCKET=<temporary-bucket>
RELIC_OBJECT_STORAGE_ACCESS_KEY=<access-key>
RELIC_OBJECT_STORAGE_SECRET_KEY=<secret-key>
```

Helm:

```yaml
seaweedfs:
  enabled: false
existingCredentialsSecret: relic          # holds objectStorageAccessKey and objectStorageSecretKey
objectStorage:
  endpoint: <endpoint>
  region: <region>
  artifactsBucket: <artifacts-bucket>
  temporaryBucket: <temporary-bucket>
```

## Testing a new service

Before you store anything that matters, check each step:

1. `/readyz` answers `ok`.
2. Upload a small file and a file of a few hundred megabytes with
   `relic artifact upload`. Download both with `relic artifact download`, and
   compare checksums.
3. Delete a file and empty it from the trash can. Wait for the GC grace period
   (`RELIC_GARBAGE_COLLECTION_GRACE_PERIOD`; you can shorten it for the test) and
   the next GC run. The file's object should then be gone from the artifacts
   bucket.
4. If you store files over 5 GiB, upload one. Relic moves it into the artifacts
   bucket with `UploadPartCopy`, which some services do not implement.

When a step fails, the server log shows the S3 error.
