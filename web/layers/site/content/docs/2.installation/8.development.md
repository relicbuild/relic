title: Development
description: Run Relic from source with go run and the web UI dev server, for working on Relic itself.
---

To work on Relic, run it with `go run` against the Compose stack's PostgreSQL and
SeaweedFS.

This command starts PostgreSQL and SeaweedFS and creates the buckets:

```bash
docker compose -f deploy/docker-compose.yml up -d postgresql seaweedfs-s3 seaweedfs-create-buckets
```

These exports point Relic at the Compose services and set the admin password:

```bash
export RELIC_DATABASE_URL='postgres://relic:relic@localhost:5432/relic?sslmode=disable'
export RELIC_OBJECT_STORAGE_ENDPOINT=http://localhost:8333
export RELIC_OBJECT_STORAGE_ACCESS_KEY=relic-dev-access-key
export RELIC_OBJECT_STORAGE_SECRET_KEY=relic-dev-secret-key-not-for-production
export RELIC_ADMIN_PASSWORD=password
```

This command starts the server:

```bash
go run ./cmd/relic server start
```

The server serves HTTPS at `https://localhost:8090`. It keeps its certificate
authority in `~/.config/relic/tls` and logs the path of `ca.crt`
([TLS](/docs/installation/configuration#tls)).

Open a second shell with the same exports. This export gives the worker a
metrics address of its own, because the server already listens on `:8091`:

```bash
export RELIC_METRICS_LISTEN_ADDRESS=:8092
```

This command starts the worker:

```bash
go run ./cmd/relic server worker
```

A plain checkout does not embed the web UI, so `/` answers "UI not built into
this binary". The `noui` build tag (`go build -tags noui`) leaves the UI out even
after `task ui` has filled `internal/app/ui/dist`. Run the UI dev server instead.
It proxies API calls to `https://localhost:8090`. `RELIC_BACKEND` sets another
address. Node.js has to trust the server's authority, which
`NODE_EXTRA_CA_CERTS` gives it.

This command installs the web dependencies:

```bash
pnpm -C web install
```

This export makes the UI dev server trust the server's authority:

```bash
export NODE_EXTRA_CA_CERTS="$HOME/.config/relic/tls/ca.crt"
```

This command starts the UI dev server:

```bash
pnpm -C web dev
```

Open `http://localhost:3000`.

Use `go run`, not `go build`, and leave no binaries in the repository. Builds for
real use come from the image.

## Taskfile

The repository's `Taskfile.yml` wraps these commands. `task` lists them:

| Task | Does |
| --- | --- |
| `task run` | Runs a single node from source on SQLite and the filesystem store in `~/.local/share/relic-dev` (`DATA_DIR`, `PORT`) |
| `task run:postgres` | Runs the same against the Compose PostgreSQL and SeaweedFS |
| `task run:docker` | Builds the image and runs it as one container on volumes |
| `task stack` | Starts the full Compose stack |
| `task install` | Builds relic with the web UI into `~/.local/bin` (`BIN_DIR`) |
| `task cli:install` | Builds relic without the web UI (`-tags noui`). It is faster and needs no Node.js |
| `task service` | Runs `install`, then `relic server setup` |
| `task gen`, `fmt`, `lint`, `test`, `test:integration`, `e2e` | Run code generation and the checks |

Every run task signs in as `admin` / `password` and uses a fixed development
encryption key. Use them for development only.

`task run` and `task run:postgres` keep the certificate authority in
`$DATA_DIR/tls` (`~/.local/share/relic-dev/tls` by default). `task web` sets
`NODE_EXTRA_CA_CERTS` to its `ca.crt`, so the UI dev server trusts the server.
