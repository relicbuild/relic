---
title: Configuration reference
description: Every environment variable the Relic server and worker read.
---

Relic reads its configuration from environment variables only. There is no
configuration file. Give the server and the worker the same values. Both connect
to the database and object storage, and both need `RELIC_ENCRYPTION_KEY`.

Durations use Go syntax, such as `90s`, `10m`, `1h` or `336h`. Switches take
`true` or `false` (`1`, `0`, `TRUE` and `False` work too). Feed and database
download URLs take an `http` or `https` URL, or `off`. Relic checks every
variable at startup. If any is wrong, Relic refuses to start and lists every error.

## Core

| Variable | Default | Meaning |
| --- | --- | --- |
| `RELIC_HTTP_LISTEN_ADDRESS` | `:8090` | Listen address, `host:port` or `:port`. It serves HTTPS unless the server runs with `--no-tls` ([TLS](#tls)). |
| `RELIC_DATABASE_URL` | (required) | A PostgreSQL URL, for example `postgres://relic:<password>@db:5432/relic?sslmode=require`. For a single node, a SQLite file such as `sqlite:///var/lib/relic/data/relic.db` ([Single node](/docs/installation/single-binary/quick-start)). |
| `RELIC_ADMIN_USERNAME`, `RELIC_ADMIN_PASSWORD` | `admin`, (none) | The first administrator. Relic creates it when no user exists and ignores these variables afterwards. |
| `RELIC_ENCRYPTION_KEY` | (none) | 32 bytes in base64 (`openssl rand -base64 32`). Relic uses it to seal these secrets in the database: token signing keys, signing key pairs, and the passwords for upstreams, replication and the LDAP manager. See [Secrets at rest](/docs/guides/operations#secrets-at-rest). |
| `RELIC_UPSTREAM_ALLOW_PRIVATE_ADDRESSES` | `false` | `true` lets remote repositories and replication reach loopback, private and link-local addresses. |
| `RELIC_WEBHOOK_ALLOW_PRIVATE_ADDRESSES` | `false` | `true` lets webhooks deliver to loopback, private and link-local addresses, such as a chat server on the company network. |

## TLS

`relic server start` serves HTTPS. It accepts TLS 1.3, whose key exchanges
include the hybrid post-quantum X25519MLKEM768, and TLS 1.2 with ECDHE key
exchange and AES-GCM or ChaCha20-Poly1305 only. `RELIC_TLS_MIN_VERSION=1.3`
refuses TLS 1.2 too. Older versions and CBC cipher suites are always refused.
`relic server start --no-tls` serves plain HTTP instead. Use it behind a proxy or
an ingress that terminates TLS, and list that proxy in `RELIC_TRUSTED_PROXIES`
([Behind a reverse proxy](/docs/guides/operations#behind-a-reverse-proxy)). The
metrics listener (`RELIC_METRICS_LISTEN_ADDRESS`) serves plain HTTP either way.

| Variable | Default | Meaning |
| --- | --- | --- |
| `RELIC_TLS_CERTIFICATE_FILE`, `RELIC_TLS_KEY_FILE` | (none) | Your own certificate: a PEM file with the certificate chain and a PEM file with its private key. Set both or neither. Relic reads them again when either file changes, so a renewed certificate, for example from cert-manager, takes effect without a restart. |
| `RELIC_TLS_DIRECTORY` | `$XDG_CONFIG_HOME/relic/tls`, or `~/.config/relic/tls`; `/etc/relic/tls` in the container image | Where Relic keeps the certificate authority and the server certificate it generates when you give it no certificate. |
| `RELIC_TLS_MIN_VERSION` | `1.2` | The oldest TLS version clients may use: `1.2` or `1.3`. |
| `RELIC_TLS_HOSTNAMES` | (none) | Comma-separated names and addresses the generated server certificate holds besides the ones Relic finds itself. |

### The generated certificate authority

Without `RELIC_TLS_CERTIFICATE_FILE` and `RELIC_TLS_KEY_FILE`, Relic creates
these files in `RELIC_TLS_DIRECTORY`:

| File | Holds |
| --- | --- |
| `ca.crt`, `ca.key` | A certificate authority, valid for 10 years. The key has mode 0600. |
| `server.crt`, `server.key` | The server certificate, signed by the authority and valid for 90 days. Relic issues a new one at every start and 30 days before it expires. |

The certificates have ECDSA P-384 keys and SHA-384 signatures. The server
certificate holds `localhost`, `127.0.0.1`, `::1`, the host name, the
machine's interface addresses, the host of `RELIC_HTTP_LISTEN_ADDRESS`, and the
names in `RELIC_TLS_HOSTNAMES`. Add the name clients use to reach the server,
such as `relic.example.com`, to `RELIC_TLS_HOSTNAMES`.

At start, the server logs the path of `ca.crt` and its SHA-256 fingerprint.
Give clients `ca.crt` and keep `ca.key` on the server. Keep the directory across
restarts and upgrades: if it is lost, Relic creates a new authority, and every
client has to trust the new one.

Each server creates its own authority. Several servers behind one load balancer
need one certificate that clients trust: set `RELIC_TLS_CERTIFICATE_FILE` and
`RELIC_TLS_KEY_FILE` on all of them.

### Trusting the authority

Clients check the server's certificate against the authorities they trust. A
certificate from an authority the client machine already trusts needs no
setup. For the generated authority, or another private one, each client needs
the authority's certificate, `ca.crt` for the generated one:

| Client | Where the certificate goes |
| --- | --- |
| relic CLI | `--ca-file ca.crt` on `relic auth login`, or accept the fingerprint it shows ([Sign in](/docs/cli/sign-in#servers-with-a-private-certificate-authority)). |
| Browsers and other tools | The operating system's trust store. |
| npm | `cafile` in `.npmrc`. |
| pip | `--cert ca.crt`, or `PIP_CERT`. |
| Go | `SSL_CERT_FILE`. |
| Docker | `/etc/docker/certs.d/<host:port>/ca.crt` on each machine that pushes or pulls. |
| Maven, Gradle | The JVM trust store. |

## Object storage

For each provider's requirements, see [Storage](/docs/installation/storage/overview).

| Variable | Default | Meaning |
| --- | --- | --- |
| `RELIC_OBJECT_STORAGE_TYPE` | `s3` | `s3` for Amazon S3 or an S3-compatible service, `azure` for Azure Blob Storage ([Azure Blob Storage](/docs/installation/storage/azure-blob-storage)), `gcs` for Google Cloud Storage ([Google Cloud Storage](/docs/installation/storage/google-cloud-storage)), or `filesystem` for a local directory ([Filesystem](/docs/installation/storage/filesystem)). |
| `RELIC_OBJECT_STORAGE_PATH` | (required with `filesystem`) | Absolute path of the directory that holds content, for example `/var/lib/relic/objects`. |
| `RELIC_OBJECT_STORAGE_ENDPOINT` | (empty) | With `s3`, an S3-compatible service's base URL, with its scheme, for example `http://seaweedfs-s3:8333`; empty for Amazon S3 itself. With `azure`, the storage account's blob URL, `https://<account>.blob.core.windows.net`. With `gcs`, only an emulator's URL. |
| `RELIC_OBJECT_STORAGE_REGION` | `us-east-1` | The region Relic signs S3 requests for. |
| `RELIC_OBJECT_STORAGE_ACCESS_KEY`, `RELIC_OBJECT_STORAGE_SECRET_KEY` | (empty) | A static S3 key pair. Leave both empty to use the AWS default credentials: IRSA, EKS Pod Identity, the instance or task role, or the environment. |
| `RELIC_OBJECT_STORAGE_SSE` | (empty) | S3 server-side encryption for every write: `AES256` or `aws:kms`. |
| `RELIC_OBJECT_STORAGE_SSE_KMS_KEY_ID` | (empty) | The KMS key for `aws:kms`; empty uses the account's default key. |
| `RELIC_OBJECT_STORAGE_STORAGE_CLASS` | (empty) | The S3 storage class for every write, for example `INTELLIGENT_TIERING`. |
| `RELIC_OBJECT_STORAGE_AZURE_CONNECTION_STRING` | (empty) | With `azure`, a connection string with the account key. Leave it empty to use the default Azure credential: workload identity, managed identity, or the environment. |
| `RELIC_OBJECT_STORAGE_ARTIFACTS_BUCKET` | `artifacts` | The bucket, or Azure container, for content. |
| `RELIC_OBJECT_STORAGE_TEMPORARY_BUCKET` | `temporary` | The bucket, or Azure container, for uploads in progress. It must be different from the artifacts bucket. |
| `RELIC_OBJECT_STORAGE_CHECKSUM` | `when_supported` | `when_supported` sends a checksum with every upload, and the storage rejects an upload that arrives damaged. `when_required` sends checksums only where S3 requires them. Use it for an S3-compatible server that answers uploads with `XAmzContentSHA256Mismatch` or a checksum error. |

## Server

| Variable | Default | Meaning |
| --- | --- | --- |
| `RELIC_MAX_CONNECTIONS` | `8192` | How many client connections Relic accepts at once. Further connections wait until Relic accepts them. `0` removes the cap. |
| `RELIC_MAX_UPLOAD_SIZE` | none | The largest file Relic accepts, in bytes or with a unit: `KiB`, `MiB`, `GiB` or `TiB`, for example `10GiB`. A larger upload fails with `413`. A local repository can set a lower limit of its own. |
| `RELIC_DATABASE_MAX_CONNECTIONS` | `20` | PostgreSQL only. The maximum number of PostgreSQL connections per server and worker process. Every request needs a connection for its lookups, so with a small pool a burst of pulls has to wait. The size is fixed rather than scaled to the node's CPUs, so the total stays predictable. The number of replicas times this value must fit within PostgreSQL's `max_connections`. `pool_max_conns` in `RELIC_DATABASE_URL` takes precedence. |
| `RELIC_DATABASE_STATEMENT_TIMEOUT` | `5m` | PostgreSQL only. The longest time a server query may run. `0` removes the limit. Migrations and the worker have no limit. |
| `RELIC_FAILED_SIGN_INS_BEFORE_BACKOFF` | `20` | How many failed password attempts a client address may make within ten minutes. After that, each further attempt waits. The wait starts at one second and doubles up to five minutes. Clients behind one address, such as CI agents behind a NAT, share the count. |
| `RELIC_TRUSTED_PROXIES` | (none) | Comma-separated CIDRs or addresses of reverse proxies. Only these proxies may set `X-Forwarded-For` and `X-Forwarded-Proto`. See [Behind a reverse proxy](/docs/guides/operations#behind-a-reverse-proxy). |
| `RELIC_SIGN_IN_NOTE` | (none) | Text the sign-in page shows under the form, such as how to reach the administrators or the credentials of a demo. Line breaks are kept. Anyone who can open the page can read it. |
| `RELIC_LDAP_CA_CERTIFICATE_FILE` | (none) | A PEM file of CA certificates to trust for LDAP servers over `ldaps://` or StartTLS, in addition to the system roots. See [LDAP](/docs/guides/security/ldap). |
| `RELIC_TRASH_ENABLED` | `true` | `false` makes deletes permanent. |
| `RELIC_INDEXER_DIR` | `/usr/local/share/relic/indexer` | The directory of `relic-indexer` builds, named `relic-indexer-<os>-<arch>`. Clients download them to scan locally. |

## Worker

| Variable | Default | Meaning |
| --- | --- | --- |
| `RELIC_TRASH_RETENTION` | `336h` | How long deleted items stay in the trash can. |
| `RELIC_AUDIT_RETENTION` | `8760h` | How long audit events are kept. |
| `RELIC_GARBAGE_COLLECTION_INTERVAL` | `10m` | How often garbage collection runs. |
| `RELIC_GARBAGE_COLLECTION_GRACE_PERIOD` | `1h` | How long unreferenced content is kept before garbage collection deletes it. Keep it longer than your longest backup copy; see [Backup](/docs/guides/operations#backup). |
| `RELIC_SCAN_SYFT_PATH`, `RELIC_SCAN_GRYPE_PATH` | `syft`, `grype` | The scanner binaries, as a name on `PATH` or a path. If either is missing, Relic Scan turns itself off. |
| `RELIC_SCAN_GITLEAKS_PATH` | `gitleaks` on `PATH` | The secrets analyzer. If Relic does not find it, secrets analysis is off. |
| `RELIC_SCAN_TRIVY_PATH` | `trivy` on `PATH` | The misconfiguration analyzer. Relic runs it with its bundled checks and no downloads. If Relic does not find it, this analysis is off. |
| `RELIC_SCAN_SCANCODE_PATH` | unset | ScanCode's `scancode`, for deep license scanning, which finds licenses in the text of files. It is slow, so it is off unless you set this. |
| `RELIC_SCAN_VULNERABILITY_DATABASE_DIR` | `/var/lib/relic/grype` | The directory of Grype's vulnerability database. Keep it on a persistent volume. |
| `RELIC_SCAN_VULNERABILITY_DATABASE_URL` | Grype's listing | Where the worker looks for vulnerability databases. It must be a `latest.json` listing, and a mirror of `https://grype.anchore.io/databases/v6/latest.json` works. With `off`, the worker downloads none, and administrators import them with `relic security database import` or *Import vulnerability database* on the System page. |
| `RELIC_MALICIOUS_PACKAGES_URL` | OSV's bucket | The source of malicious-package advisories, read from `<url>/<ecosystem>/all.zip`. This is OSV's layout, so a mirror in a generic repository works. `off` turns the feed off. |
| `RELIC_SCAN_GOVULNCHECK_PATH` | `govulncheck` on `PATH` | govulncheck, which tells whether Go executables call the vulnerable code of their findings. The image ships it; without it Go findings stay of unknown reachability. |
| `RELIC_SCAN_GO_VULNERABILITY_DATABASE_URL` | `https://vuln.go.dev/vulndb.zip` | The Go vulnerability database govulncheck reads, downloaded with Grype's database. A copy in a generic repository works. `off` downloads none. |
| `RELIC_END_OF_LIFE_URL` | endoflife.date | endoflife.date's full product dump (`/api/v1/products/full`), read daily to find components past or near end of life. A copy of it works. `off` reads none; `relic security end-of-life import` still can. |
| `RELIC_SECRET_VALIDATION_ENABLED` | `false` | `true` asks the provider of each secret found in content (GitHub, GitLab, Slack, npm, Stripe) whether it still accepts it. Off by default: it sends each secret to its provider. |
| `RELIC_SECRET_VALIDATION_PROVIDERS` | all | Comma-separated providers to ask: `github`, `gitlab`, `slack`, `npm`, `stripe`. |
| `RELIC_DEPS_DEV_URL` | off | deps.dev's API (`https://api.deps.dev`) or a mirror, to flag deprecated and unmaintained packages. Off by default: every check sends a package name and version to it. |
| `RELIC_CVE_EPSS_URL` | FIRST's daily EPSS scores | The source of EPSS scores (`.csv.gz`). `off` turns the feed off. |
| `RELIC_CVE_KEV_URL` | CISA's KEV catalog | The source of the Known Exploited Vulnerabilities catalog (JSON). `off` turns the feed off. |
| `RELIC_CVE_RECORDS_URL` | `https://cveawg.mitre.org/api/cve` | A base URL that serves CVE JSON 5 records at `<url>/<CVE-ID>`. `off` turns this source off. |

In an air-gapped network, point the CVE feeds at internal mirrors or set them to
`off`.

## Telemetry

The server and the worker both read these variables. See [Monitoring](/docs/guides/monitoring).

| Variable | Default | Meaning |
| --- | --- | --- |
| `RELIC_METRICS_LISTEN_ADDRESS` | `:8091` | The address that serves `/metrics` over plain HTTP, separate from the API port. `off` turns this listener off. |
| `RELIC_PROFILING_ENABLED` | `false` | `true` adds `/debug/pprof/` to the metrics listener. |
| `RELIC_METRICS_REPOSITORY_LABEL` | `false` | `true` adds the repository name as a label to the artifact, upstream, cache and replication series. The number of series then grows with the number of repositories. |
| `RELIC_LOG_LEVEL` | `info` | `debug`, `info`, `warn` or `error`. |
| `RELIC_LOG_FORMAT` | `json` | `json` or `text`. |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | (none) | The OTLP/HTTP base URL, such as `http://collector:4318`. Relic appends `/v1/traces` and `/v1/logs`. If neither this nor `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` is set, tracing is off. |
| `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`, `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` | (none) | Full URLs for each signal. Relic uses them as given. |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | `http/protobuf` | The only supported protocol. Relic refuses to start with `grpc`. |
| `OTEL_EXPORTER_OTLP_HEADERS` | (none) | Headers for the collector, such as an authorization token. |
| `OTEL_SERVICE_NAME` | `relic-server`, `relic-worker` | The service name on traces and log records. |
| `OTEL_RESOURCE_ATTRIBUTES` | (none) | Extra resource attributes, `key=value,…`. |
| `OTEL_TRACES_SAMPLER`, `OTEL_TRACES_SAMPLER_ARG` | `parentbased_always_on` | `always_on`, `always_off`, `traceidratio`, or their `parentbased_` forms. The argument is the ratio. |
| `OTEL_TRACES_EXPORTER` | `otlp` | `none` turns tracing off. |
| `OTEL_LOGS_EXPORTER` | `none` | `otlp` also sends every log record to the collector. |
| `OTEL_SDK_DISABLED` | `false` | `true` turns traces and OTLP logs off. |
