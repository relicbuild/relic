## Methods

| Method | Use | Database and storage |
| --- | --- | --- |
| [Single binary](/docs/installation/single-binary/quick-start) | One machine. Download the binary and run `relic server setup`. | SQLite and a local directory. Nothing else to run. |
| [Docker](/docs/installation/docker/quick-start) | One container, or a server and a worker that use your PostgreSQL and S3. The Compose stack is for development and evaluation. | SQLite and a volume, or PostgreSQL and S3. Compose brings both. |
| [Kubernetes](/docs/installation/kubernetes/overview) | Production, with several server replicas, failover and backups. | CloudNativePG and SeaweedFS by default, or your own. |
| [Cloudflare](/docs/installation/cloudflare) | One container on Cloudflare behind a Worker, without a server of your own. | Your PostgreSQL and R2. |

Start with the single binary. Move to PostgreSQL when one machine is not
enough ([Moving to PostgreSQL](/docs/installation/single-binary/operations#moving-between-postgresql-and-sqlite)).

For production, use:

- the Helm chart
- CloudNativePG backups, or an external PostgreSQL with point-in-time recovery
- a replicated S3 store

Relic is developed and tested against [SeaweedFS](/docs/installation/storage/seaweedfs).

## Parts

| Part | Notes |
| --- | --- |
| `relic server start` | Serves the HTTP APIs and the web UI over HTTPS ([TLS](/docs/installation/configuration#tls)), or plain HTTP with `--no-tls`. It is stateless, so you can run any number of replicas. |
| `relic server worker` | Runs background jobs: scanning, garbage collection, replication and trash retention. One replica is enough. |
| `relic server start --worker` | Runs the server and the worker in one process, for a single-node installation. |
| `relic server migrate` | Applies the database migrations and exits. Needs `RELIC_DATABASE_URL` only. |
| PostgreSQL or SQLite | Holds all metadata and is the system of record. Use PostgreSQL for several replicas (the Compose stack uses PostgreSQL 18, the Helm chart PostgreSQL 16). Use SQLite for a single node. |
| Object storage | Holds the content, in two S3-compatible buckets or, on a single node, a local directory. See [Storage](/docs/installation/storage/overview). |

Every part is the same binary (in the image, `/relic`) and reads the same
[environment variables](/docs/installation/configuration).

The server and the worker apply database migrations at startup. While they do,
they hold a lock: a PostgreSQL advisory lock, or, on Linux and macOS, a file
beside the SQLite database. Several processes can therefore start at once. `relic server migrate`
runs the migrations as a separate step, for example before an upgrade.

Relic Scan runs Syft, Grype, Gitleaks and Trivy. The image includes them. If you
run the binary, install the scanners you want on the `PATH`. Without them, the
server runs with scanning off.

Relic's license and the licenses of the software it is built from and shipped
with are in the image under `/usr/share/licenses/relic/`, and in each release
archive as `LICENSE` and `THIRD_PARTY_NOTICES`.

## After installing

1. Sign in at `https://relic.example.com/` as `admin` with the password from
   `RELIC_ADMIN_PASSWORD`.
2. [Sign in with the relic CLI](/docs/cli/sign-in).
3. Set up backups of the database, the content and `RELIC_ENCRYPTION_KEY`. See
   [single node](/docs/installation/single-binary/operations#backups),
   [PostgreSQL and S3](/docs/guides/operations#backup).
