title: JFrog compatibility
description: Use the JFrog CLI, the JFrog® Artifactory® and Xray® REST APIs and the JFrog Go SDK against Relic.
---

Relic serves the APIs of JFrog® Artifactory® and Xray®. The JFrog CLI (`jf`), the
package managers it configures, and code written for those APIs work against
Relic unchanged.

To move an existing Artifactory into Relic, see
[Migrating from Artifactory](/docs/cli/import).

## Configure jf

Create an access token in the UI, under **Set me up** or **Access tokens**.
Then add Relic to jf as a server:

```bash
jf config add relic --url https://relic.example.com --user <you> --access-token <token> --interactive=false
```

Check that jf can reach Relic:

```bash
jf rt ping --server-id relic
```

`jf login` also works. jf opens the UI, you sign in and approve the code that jf
shows, and jf stores a token. Directory (LDAP) users sign in the same ways as
local users.

If Relic's certificate comes from a private CA, such as the one Relic generates
([TLS](/docs/installation/configuration#tls)), add the CA certificate to the
system trust store of the machine that runs jf.

## Endpoints jf uses

| jf commands | Relic serves |
| --- | --- |
| `jf rt ...`, package managers jf configures | `/artifactory/...` |
| `jf audit`, `jf scan`, `jf xr ...` | `/xray/...` (Relic Scan) |
| `jf rbc`, `jf rbp`, ... | `/lifecycle/...` |
| `jf evd ...` | `/evidence/...` and `/onemodel/...` |
| tokens, `jf login` | `/access/...` |
| `docker`, `jf docker` | `/v2/...` |

Package managers configured by jf use the paths under `/artifactory/`, such as
`/artifactory/api/npm/<repo>/`. Maven and Gradle use `/artifactory/<repo>/`, and
Docker uses `/v2/`. Clients configured by `relic package setup` use Relic's own
paths, such as `/npm/<repo>/`. Both reach the same repositories.

## Package managers

For npm, yarn and pnpm, configure the resolve and deploy repositories:

```bash
jf npmc --server-id-resolve relic --repo-resolve npm --server-id-deploy relic --repo-deploy npm-local
```

Install the dependencies through jf:

```bash
jf npm install
```

Publish the package through jf:

```bash
jf npm publish
```

For Maven, configure the resolve and deploy repositories:

```bash
jf mvnc --server-id-resolve relic --repo-resolve-releases maven --repo-resolve-snapshots maven \
  --server-id-deploy relic --repo-deploy-releases maven-local --repo-deploy-snapshots maven-local
```

Deploy through jf:

```bash
jf mvn deploy
```

Gradle works the same way with `jf gradlec` and `jf gradle`.

For Go, configure the resolve and deploy repositories:

```bash
jf goc --server-id-resolve relic --repo-resolve go --server-id-deploy relic --repo-deploy go-local
```

Build the module:

```bash
jf go build ./...
```

Publish a module version to the deploy repository:

```bash
jf go-publish v1.2.3
```

For PyPI, configure the resolve repository:

```bash
jf pipc --server-id-resolve relic --repo-resolve pypi
```

Install a package with pip:

```bash
jf pip install requests
```

Poetry has its own configuration. Configure its resolve repository:

```bash
jf poetry-config --server-id-resolve relic --repo-resolve pypi
```

Install a project's dependencies with Poetry:

```bash
jf poetry install
```

Push a Docker image and record build info:

```bash
jf docker push relic.example.com/docker-local/app:1.0 --build-name app --build-number 1
```

NuGet, Terraform and Hugging Face also work. For NuGet, configure the resolve
repository:

```bash
jf dotnetc --server-id-resolve relic --repo-resolve nuget
```

Restore NuGet packages:

```bash
jf dotnet restore
```

For Terraform, configure the deploy repository:

```bash
jf tfc --server-id-deploy relic --repo-deploy terraform-local
```

Publish each module under the current directory:

```bash
jf tf publish --namespace acme --provider aws --tag v1.0.0
```

Upload a Hugging Face model:

```bash
jf hf upload <folder> <org>/<model> --repo-key hf
```

`jf hf download` downloads one.

Upload generic files:

```bash
jf rt upload "build/*" generic-local/app/
```

Download them:

```bash
jf rt download "generic-local/app/*"
```

Set a property on the files:

```bash
jf rt set-props "generic-local/app/*" "release=1.0"
```

Search for them:

```bash
jf rt search "generic-local/app/*"
```

## Configuration

`jf rt repo-create`, `jf rt permission-target-create` and
`jf rt replication-create` create repositories, permission targets and
replications. Relic treats them as its own.

Relic also serves these paths:

| Resource | Path |
| --- | --- |
| LDAP settings | `/access/api/v1/ldap/settings`, `/access/api/v1/ldap/groups` |
| Trash can | `/artifactory/api/trash/` |

Restore an item from the trash can:

```bash
jf rt curl -XPOST "/api/trash/restore/libs-local/org/app/1.0/app-1.0.jar"
```

Empty the trash can:

```bash
jf rt curl -XPOST "/api/trash/empty"
```

## Builds

The package-manager commands above record build info with `--build-name` and
`--build-number`. Publish the build info:

```bash
jf rt build-publish app 1
```

`jf rt build-collect-env`, `build-add-git`, `build-add-dependencies`,
`build-append`, `build-promote`, `build-discard`, `build-clean`,
`build-docker-create` and `docker-promote` also work. Published builds appear
under **Builds** in the UI.

## Scanning

- `jf audit` and `jf scan` scan source trees and binaries locally. They use the
  `relic-indexer` builds that Relic serves (`RELIC_INDEXER_DIR`). The Docker image
  includes them; a [single-binary installation](/docs/installation/single-binary/quick-start#local-scans-with-the-jfrog-cli)
  needs them built.
- `jf build-scan` scans a published build. Build scans and `jf audit` report
  vulnerabilities only. License policies apply to stored artifacts.
- `jf scan --licenses` lists the licenses `relic-indexer` finds. `jf audit
  --licenses` lists each dependency as `Unknown`: Relic Scan reports no
  licenses for a dependency tree.
- `jf curation-audit` reports every package as approved: Relic has no curation
  policies. The audit downloads packages under the same download blocking as
  any other download. When a Relic Scan watch blocks a package that the
  package manager needs to resolve the dependency tree, the audit stops with
  HTTP 403 and does not list that package.
- `jf evd` needs an access token. Configure the jf server with `--access-token`.

## Limits

- `--archive-entries` is not supported by `jf rt search`, `download`, `copy`,
  `move`, `delete` or `set-props`. Relic does not index the files inside
  archives for search and answers such a query with 400. The **Archive** tab of
  an artifact in the UI lists the files inside it.
- `jf rbp --promotion-type move` copies the artifacts: they stay in the
  repositories of the previous environment. jf reports success; the promotion
  record's messages say that the move was performed as a copy.

## REST APIs

| API | Path |
| --- | --- |
| Artifactory® | `/artifactory/` |
| Xray® | `/xray/` |
| Access | `/access/` |
| Lifecycle | `/lifecycle/` |
| Evidence | `/evidence/` |

These APIs accept Basic credentials or an access token. JFrog's documentation
describes them. The [API reference](/api-reference) covers the Relic API only.

Run an AQL search:

```bash
curl -u <user>:<token> -X POST https://relic.example.com/artifactory/api/search/aql \
  -d 'items.find({"repo":"libs-local","name":{"$match":"*.jar"}})'
```

Relic honours the UI's session cookie under `/api/` only. A browser page
therefore cannot drive these APIs.

## JFrog Go SDK

Code written with [jfrog-client-go](https://github.com/jfrog/jfrog-client-go) works
against Relic unchanged. Point the service details at Relic's `/artifactory/` URL:

```go
details := auth.NewArtifactoryDetails()
details.SetUrl("https://relic.example.com/artifactory/")
details.SetUser("ci")
details.SetPassword(os.Getenv("RELIC_TOKEN")) // a password or an access token

cfg, err := config.NewConfigBuilder().SetServiceDetails(details).Build()
if err != nil {
	return err
}
rt, err := artifactory.New(cfg)
if err != nil {
	return err
}

up := services.NewUploadParams()
up.Pattern, up.Target, up.Flat = "build/*.jar", "libs-local/org/app/1.0/", true
uploaded, failed, err := rt.UploadFiles(artifactory.UploadServiceOptions{FailFast: true}, up)
```

Relic's test suite calls every Artifactory REST route that Relic serves through
jfrog-client-go, pinned to v1.55.0. The suite fails when someone adds a route
without a test for it.

## Not provided

Relic answers 404, with "Relic does not provide" and the product's name, to the
AppTrust, Distribution v1, Mission Control, Pipelines and Workers routes, so jf
fails at once instead of retrying. `jf release-bundle-distribute` gets a 404 with
"Relic does not distribute release bundles": Relic has no distribution targets.
`jf rt transfer-*` fails cleanly. To move an Artifactory
into Relic, use [`relic import artifactory`](/docs/cli/import).
